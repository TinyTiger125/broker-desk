# Broker Desk 日本語プロダクト用語辞書

更新日: 2026-07-14
ステータス: 事業レビュー用ドラフト

## この辞書の目的

この辞書は、Broker Desk の画面文言を日本の不動産仲介業務に合う言葉へ統一するためのものです。

レビュー対象は、画面のモジュール名、ボタン名、状態名、入力項目の説明、操作案内です。

レビュー対象ではないもの:

- 顧客名、担当者名
- 住所
- 物件名、建物名、部屋番号
- 会社名
- アップロードされたファイル名
- 保証会社の公式申込書に印刷されている原文ラベル

これらは元資料の事実なので、画面言語に合わせて無理に翻訳しません。

## プロダクトの基本表現

Broker Desk V1 の基本導線は次の通りです。

```text
資料を入れる -> 足りない項目だけ確認する -> 申込書を出す
```

画面文言は、この流れが一目で分かることを優先します。

ユーザーに見せない方がよい言葉:

- フィールド
- マッピング
- key
- スキーマ
- システム判断
- 座標
- テンプレート校正
- 保存項目 ID

| 整理ページ | 情報を整理 | 案件情報を整理 | 案件単位で足りない情報を補う画面だと分かる。 |

## 主要オブジェクト名

| 概念 | 推奨表現 | 使い方 |
| --- | --- | --- |
| Case | 案件 | 申込、賃貸、売買、保証会社申請など、1つの業務単位。 |
| Party | 関係者 | 申込者、借主、貸主、保証人、緊急連絡先、法人担当者など。 |
| Property | 物件 | 建物・部屋・対象不動産。日本語 UI では`物件`で統一。 |
| Source material | 資料 | アップロード、スキャン、Excel、PDF、画像、手入力などの元情報。 |
| Unassigned material | 未分類資料 | まだ案件・関係者・物件に紐づいていない資料。 |
| Needs work material | 未整理資料 | 紐づき先は分かるが、中身の確認や補完が残っている資料。 |
| Output document | 申込書 / 出力書類 | 保証会社用途では`申込書`を優先。 |
| Ledger/List | 一覧 | 通常画面では`一覧`。内部管理や台帳性を出す画面だけ`台帳`。 |

## 操作用語

| 場面 | 推奨表現 | 避けたい表現 | 理由 |
| --- | --- | --- | --- |
| 資料をアップロードして読ませる | 資料を読み取る | ファイルをインポート | ユーザーの目的は読み取り結果を得ること。 |
| 案件を作る | 案件を作成 | レコードを作成 | 業務単位を作っているので`案件`を出す。 |
| 関係者を追加 | 関係者を追加 | 主体を追加 | 日本語実務では`関係者`が自然。 |
| 物件を追加 | 物件を追加 | アセットを追加 | 不動産業務では`物件`。 |
| 足りない情報を入れる | 続けて整理 | フィールドを編集 | ユーザーは項目処理ではなく案件整理をしている。 |
| 読取結果を採用する | 確認結果を保存 | 標準フィールドへ書き込み | 内部データモデルを見せない。 |
| 申込書を作る | 申込書を出力 | PDFを生成 | PDF は形式であり、ユーザーの目的は申込書。 |
| 元の案件へ戻る | 案件を確認 / 案件へ戻る | レコードを開く | 業務対象を明確にする。 |

## 状態用語

| 状態 | 推奨表現 | 使う場面 | 注意 |
| --- | --- | --- | --- |
| Ready | 整理済み | 基本情報がそろい、次の作業に進める。 | `確認済み`とは分ける。 |
| Needs work | 未整理 | 対応すべき項目が残っている。 | 何が残っているかを近くに表示する。 |
| Missing required fields | 未入力 | 必須または必要項目が空。 | `不明`とは違う。 |
| Extraction needs review | 要確認 | 読み取れたが、人の確認が必要。 | 空欄には使わない。 |
| Confirmed by user | 確認済み | ユーザーが採用・確認した値。 | `整理済み`とは違う。 |
| Edited by user | 修正済み | ユーザーが読み取り結果を直した。 | 変更履歴に使う。 |
| Conflict | 不一致 | 複数資料の値が食い違う。 | まだ`誤り`とは言わない。 |
| Not applicable | 該当なし | 今回の案件では不要な項目。 | `採用しない`とは違う。 |
| Rejected suggestion | 採用しない | 読み取り候補を使わない判断。 | 項目自体が不要なら`該当なし`。 |
| Unknown | 判断できない | 資料から判断できない。 | `不明`より操作意図が明確。 |
| Unassigned | 未分類 | どの案件・関係者・物件に属するか未確定。 | `未整理`と分ける。 |

## 入力項目まわりの言葉

| 避けたい言葉 | 推奨表現 | 理由 |
| --- | --- | --- |
| フィールド | 項目 / 入力項目 | 一般ユーザーには項目の方が自然。 |
| フィールドマッピング | 保存先 / 対応先 | 内部処理を見せない。 |
| 保存項目 | 保存先 | ユーザーは「どこに保存されるか」を知りたい。 |
| システム判断 | 自動読取結果 / 非表示 | 内部能力の説明は通常不要。 |
| プレビュー値 | 読取結果 | 何の値か分かりやすい。 |
| key / ID | 表示しない / 番号 | 業務上必要な番号だけ表示する。 |
| contract_number | 契約番号 | 内部キーをそのまま出さない。 |

| 概念 | 推奨表現 | 判断 |

## レビュー表の記入ルール

レビュー表では `suggested_text` 列だけを編集します。

変更不要なら空欄のままにします。

`source=i18n` の行は自動で取り込めます。

`source=hardcoded` の行は、先にエンジニア側で i18n 化してから取り込みます。
