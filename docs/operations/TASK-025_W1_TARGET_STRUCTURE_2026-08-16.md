## 1. 推荐结论

采用一个两阶段结构，不把 `/organize-center` 做成一个混合对象表，也不把案件详情编辑塞回信息整理中心：

```text
/organize-center
整理对象选择器（Object-type Selector）
    ↓ 选择一个对象类型
/organize-center?type=case|party|property|inbox
List Report
    ↓ 通过对象名称原生链接打开
案件、主体、物件或资料归属流程
```

推荐保留四个独立入口：案件、主体、物件、待归属资料。它们可以共用筛选栏、结果行、空态和错误表达，但不合并业务权威、状态来源或编辑器。

这保留了用户真正的任务顺序：先找到正确对象，再进入后续处理。页面本身不定义输出资格，也不承担案件详情编辑、案件确认或申请书下载。

## 3. 页面信息结构

### 3.1 整理对象选择器：`/organize-center`

页面只回答：“我要整理哪一类对象？”

1. 页面标题：`整理信息`。
2. 页面副标题：说明这里用于查找对象并进入后续处理，不暗示已经可以输出文件。
3. 四个独立入口：
   - 案件：申请、合同、费用及案件资料。
   - 主体：客户、业主、租客、保证人等主体记录。
   - 物件：地址、房号、租金和费用等物件记录。
   - 待归属资料：尚未确定归属的资料，不与案件、主体或物件混成同一种对象。
4. 每个入口显示：对象数量、权威待处理数量（如有）、对象类型名称和一句业务说明。
5. 数量为零时仍显示入口和明确空态，不隐藏对象类型。
6. 入口使用链接进入对应 List Report；不通过双击或不可见手势进入。

入口状态只描述该类型的信息整理状态。不得使用无条件“已完成”表示整个案件完成，也不得在此阶段显示“可输出”或类似输出资格暗示。

### 3.2 List Report：`/organize-center?type=...`

页面回答：“这一类对象中，我要找哪一个？”

结构顺序固定为：

1. 返回对象选择器：返回 `/organize-center`，明确这是返回模块首页，不承诺保留临时筛选。
2. 当前对象类型标题：例如“案件”“主体”“物件”“待归属资料”。
3. Filter Bar：关键字、生命周期筛选、清除筛选。
4. 结果摘要：当前结果数量、当前页范围和当前生命周期范围。
5. 结果结构：按当前对象类型展示稳定的结果行，不把四类对象混在同一张表中。
6. 空态、无结果、权限拒绝、加载和系统错误各自表达，不互相伪装。

默认保留当前 URL 语义：`type`、`q`、`lifecycle`、`page`。这些状态可分享、可返回；不建立筛选数据库，也不建立独立 selected 状态。

## 4. 结果行与操作层级

### 4.1 结果行内容

每行按以下顺序显示：

1. 对象名称：作为明确、可见、可键盘访问的主要链接。
2. 对象类型或对象子类型：只在有助于区分时显示。
3. 业务关系信息：例如案件中的申请人/物件，主体的关联对象，物件的使用位置。
4. 信息整理状态：只描述资料不足、有差异、待确认或当前无整理问题。
5. 生命周期：有效或已归档，与信息整理状态分开。
6. 更新时间或其他辅助信息：不得抢占对象名称和进入操作。
7. 行尾箭头：只作为同一对象名称链接的视觉提示，不增加第二个 Tab 停靠点。
8. 归档：放入次级操作或更多菜单，不嵌入主要对象链接。

普通结果不做大型卡片化。桌面端使用稳定列关系和分隔线组织信息；窄屏端将同一行顺序堆叠，不改变业务含义。

### 4.2 对象链接与操作层级

- 不建立批量操作、工作区选择或独立 selected 状态；W1没有需要它们的用户任务。
- 对象名称是唯一主要链接，使用原生可访问链接进入对象详情或对应处理流程。
- Tab 直接聚焦对象名称链接；Enter 使用原生链接行为打开。
- 结果行只使用 hover 和 focus 表达，不称为“选中”，不保存额外选择状态。
- 双击可以删除；即使暂时保留，也不作为验收能力或主要发现路径。
- 行尾箭头只是同一主要链接的视觉提示，不增加重复 Tab 停靠点。
- 归档进入次级菜单或独立次级操作，并保留确认、处理中反馈和失败恢复。
- 打开链接必须保留对象类型和对象 ID 的正确业务路由，不通过通用对象详情页合并案件、主体和物件。

### 4.3 归档

- 归档是有数据生命周期影响的次级风险操作。
- 视觉权重低于打开对象，不与对象名称链接竞争。
- 需要明确确认、处理中反馈和失败恢复。
- 归档后应按当前生命周期筛选规则返回，不改变其他对象的业务状态。

## 5. 按对象类型的状态契约

W1只定义信息整理状态，不定义输出资格、案件级确认或申请书状态。状态必须由对象类型自己的权威数据和明确规则判定；不得用局部 `reviewed`、确认字段数量或资料关联状态单独推导“案件整体完成”或“可以输出”。

通用优先级为：

1. 资料不足：缺少该对象类型规则要求的基础资料。
2. 有差异：存在明确、可定位的资料或领域冲突。
3. 待确认：存在权威的待确认内容或待处理数量。
4. 当前无整理问题：在当前对象类型和当前整理规则范围内没有上述问题。

“待处理 N”是权威数量的附加事实，不被压缩成一个笼统状态；只完成局部阶段时使用带范围的文案，例如“基础资料已整理”。

| 对象类型 | 权威数据来源 | 判定条件与优先级 | 显示文案 | 不得推导出的含义 |
|---|---|---|---|---|
| 案件 | 案件记录、案件领域完整性/冲突规则、服务端权威待处理数量 | 资料不足 → 有差异 → 待确认 → 当前无整理问题；若只有基础资料规则通过，显示范围化结果 | `资料不足`、`有差异`、`待确认`、`待处理 N`、`基础资料已整理`或`当前无整理问题` | 不得表示案件整体完成、案件级确认完成、申请书可输出或下载可用 |
| 主体 | 主体记录、角色和联系人等主体领域规则、服务端返回的待处理信息 | 角色/基础资料缺失 → 明确差异 → 待确认 → 当前无整理问题 | `资料不足`、`有差异`、`待确认`或`当前无整理问题` | 不得表示关联案件、物件或申请书已完成 |
| 物件 | 物件记录、地址/房号/租金等物件领域规则、服务端返回的待处理信息 | 基础物件资料缺失 → 明确差异 → 待确认 → 当前无整理问题 | `资料不足`、`有差异`、`待确认`或`当前无整理问题` | 不得表示案件、主体或输出资料已完成 |
| 待归属资料 | 导入资料记录、归属状态和资料处理结果 | 未归属优先；资料处理失败或不足其次；需要人工判断时为待确认 | `待归属`、`资料不足`、`待确认`或具体失败提示 | 不得表示资料已属于案件、主体或物件，也不得表示案件可以输出 |

生命周期 `有效 / 已归档` 独立于以上整理状态显示。正式中文、日文和韩文词汇继续由唯一术语来源决定；本契约规定的是业务含义，禁止把当前“已完成”机械替换成无限定的“已整理”。

## 6. 筛选、空态和错误

### Filter Bar

- 关键字搜索针对当前对象类型，不跨类型偷偷改变结果权威。
- 生命周期筛选至少支持有效、已归档和全部；默认有效。
- 搜索、筛选和清除后更新 URL，并保留当前页面位置；清除后输入框、结果和 URL 同步为空。
- 结果数量随当前筛选和 `page` 更新；没有结果时明确显示“当前条件没有结果”并提供清除筛选。
- Filter Bar 不承担对象编辑、案件保存或输出操作。

### 状态区分

- 初始空数据：该对象类型目前没有记录，提供创建或导入入口时必须明确其业务语义。
- 无搜索结果：有该类型能力，但当前条件没有匹配结果；提供清除筛选。
- 资料不足：对象存在，但业务资料不完整；进入对象继续处理。
- 权限拒绝：用户无权访问该类型或对象；不得伪装成空列表。
- 系统错误：数据加载失败；显示可重试和返回路径，不泄露服务端细节。
- 加载中：保留页面结构，不显示成无数据或已完成。

## 7. 返回语义与上下文

### 已冻结的一级导航语义

顶部一级导航“整理信息”继续返回 `/organize-center` 对象选择器，并重置临时筛选和列表上下文。这是模块入口语义，不修改案件详情页来强行保存列表状态。

### List Report的浏览历史语义

从列表打开对象后，浏览器历史返回应恢复：

- `type`、`q`、`lifecycle` 和 `page` URL 条件；
- 搜索输入框值；
- 列表滚动位置；
- 触发打开的对象名称链接焦点（若该对象仍在当前结果集中）。

不恢复独立 selected 状态。筛选、分页和列表上下文通过 URL/浏览器历史状态完成，不写入数据库，不改变案件、主体或物件保存逻辑。短列表无法形成真实滚动位移时，验收必须标记“滚动恢复未验证”，不能判定失败或通过。

## 10. 可执行验收场景

目标结构获产品批准后，单页实现至少按以下顺序验收：

1. 进入 `/organize-center`，看到四个独立对象入口；空对象类型也有明确数量和空态。
2. 进入案件 List Report，记录 URL、对象类型、结果数量和默认生命周期。
3. 输入唯一关键字，确认输入框、URL 和结果数量一致；Tab 聚焦对象名称链接。
4. 输入不存在的关键字，确认显示无结果状态并可清除恢复。
5. 点击可见的案件名称链接打开案件；不依赖双击。
6. Tab 聚焦对象名称链接，Enter 使用原生链接行为打开；行尾箭头不产生重复 Tab 停靠点，归档位于次级操作。
7. 通过浏览器历史返回，验证 `type`、`q`、`lifecycle`、`page`、列表滚动和触发链接焦点恢复；不验证也不恢复独立 selected 状态；若列表过短，滚动恢复记为未验证。
8. 从案件使用一级导航“整理信息”，确认回到对象选择器且临时筛选清空，不把该行为误判为列表历史恢复失败。
9. 分别进入主体、物件和待归属资料，确认入口、路由、字段摘要和权限没有互相冒充。
10. 对同一案件对照列表状态和案件详情进度，确认列表状态符合对象类型契约，不使用会被理解成整体完成或输出可用的无条件文案。
11. 在 1440px、768px、390px 验证结果结构、长文本、无横向溢出和主要操作可见；补充真实 Chrome 缩放记录。
12. 在安全测试环境验证加载、无数据、无结果、权限拒绝和系统错误；无法安全制造的状态标记为未验证。
