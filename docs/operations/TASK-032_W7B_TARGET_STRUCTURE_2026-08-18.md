# TASK-032 / W7-B Checkpoint B：客户 Responsive Form 目标结构

- 日期：2026-08-18
- 状态：Checkpoint C 通过；按页面结构迁移口径收口
- 目标路由：`/clients/new`、`/clients/[id]/edit`
- 结构基线：Layout System V1、TASK-024 Responsive Form 试点和已批准的客户 List Report 层级

## 1. 页面定位与模式边界

两页统一采用客户 Responsive Form。统一的是客户字段定义、分组顺序、术语、解析/校验契约、错误语言和操作层级；新建与编辑继续保留各自页面控制器、初始值、对象存在性检查和成功跳转，不把两条流程强行合成一个充满 `mode` 分支的单体页面。

本任务不复制物件字段模型，不吸收客户详情 Object Page、跟进历史、报价/提案流程、输出链路或关系章节。`/clients/[id]` 只作为导航边界；跟进记录仍在其独立业务章节维护。

目标首屏只回答“正在维护哪个客户、需要填写哪些客户事实以及如何保存或取消”，不展示完成度、进度条、AI 审核、输出资格或第二套详情。

## 2. 共享字段和业务分组

创建与编辑使用同一字段组合、术语、顺序和服务端解析。页面采用连续的表单表面、网格和留白，不做每组一张重卡片。

### 2.1 基本信息

- 姓名
- 电话
- LINE ID
- 邮箱

### 2.2 需求条件

- 预算下限、预算上限
- 预算类型
- 意向区域
- 第一意向区域、第二意向区域
- 用途
- 期望入住/运营时间
- 贷款预审状态

### 2.3 客户管理

- 阶段
- 温度
- 下次跟进日期 `nextFollowUpAt`

`nextFollowUpAt` 仅表示下一次计划日期。跟进记录、类型、内容、下一动作和历史不在表单中展示或维护。

### 2.4 合同与法定信息

- 媒介合同类型、签订日、到期日
- 35 条重要事项说明日
- 37 条合同书面交付日
- 个人信息同意确认日
- AML 状态

### 2.5 备注

备注是独立的可选文本区，不自动拼接规则抽取内容，不把备注长度或非空解释成完成状态。

## 3. 权威字段、必填和默认值

### 3.1 权威来源

页面只把 `clients` 记录及现有 memory/PostgreSQL 适配返回的字段当作客户事实。`stage`、`purpose`、`temperature` 使用域层显式枚举值；不从姓名、备注、跟进数量、关键词或其他页面状态推断。

电话继续必填是当前数据库和 Action 非空契约的兼容约束，不是长期产品结论。未来“姓名必填＋至少一种联系方式”作为领域问题记录，不在 W7-B 修改数据库或阻塞实现。

### 3.2 创建模式

- 姓名：必填，必须由用户输入；不得生成默认名称。
- 电话：必填，沿用当前兼容模型约束。
- 阶段：可初始显示 `lead`，含义是新进入系统的线索初始阶段；该值仍显示在表单中并可由用户确认/修改。
- 用途、温度：显示“请选择”占位并要求用户明确选择；不得静默落为 `self_use`、`medium`。
- 贷款预审、媒介合同、AML 保留现有枚举的准确业务文案：`not_applied`、`none`、`not_required` 不改名、不解释为“未确认”，也不新增 `unknown/unconfirmed` 枚举。可以增加安静的辅助说明“创建时的系统初始状态，不表示人工核验完成”，但不得显示“已确认”“已完成”或合规通过徽章。
- 其余客户字段可选，空值规则见下一节。

### 3.3 编辑模式

- 以当前客户记录填充已有值，不用创建默认值覆盖既有事实。
- 请求缺少用途、温度或其他必需枚举，或值被篡改为非法值时，服务端拒绝并保留原记录；不得悄悄回落到 `lead`、`self_use` 或 `medium`。
- 记录实际缺失的可选值继续显示未设置；不得把缺失改写为默认业务状态。

## 4. 空值、数值和日期契约

- 可选文本留空保存为未设置：表单层可使用空字符串，解析层统一转为 `undefined`，PostgreSQL 适配写入 `NULL`。
- 预算留空保存为未设置。
- 用户明确输入 `0` 或负数预算时拒绝；预算为零没有有效客户业务意义。
- 预算下限大于预算上限时，返回字段级错误；不能只在页面显示提示后继续写入。
- 非法数字、非法日期和非法枚举均由服务端拒绝；HTML `min`/`type` 只是辅助提示，不能替代服务端校验。
- 日期留空不得自动生成今天日期；个人信息同意日期只能来自用户明确输入或未来另行批准的事实来源。
- 不复制物件任务中“真实零值有效”的费用规则；客户预算的零值按本任务拒绝。

## 5. 模板和备忘录抽取边界

从 `/clients/new` 的默认主流程移除：

- 推荐模板
- 置信度和关键词推断
- 自动填充准备
- 自动生成同意日期
- 自动生成阶段、温度、AML 或媒介合同状态

只移除页面调用和默认展示，不删除或重写：

- `src/lib/client-form-template.ts`
- `src/lib/client-intake-parser.ts`

理由是当前规则会把关键词推断带入业务字段，固定置信度未经产品验证，且可将 `personalInfoConsentAt` 自动设置为当天。这些内容会把客户创建页变成用户审查算法的工作台，违背“正常信息安静、辅助只处理异常”的产品边界。

未来若恢复，必须另立“来源文本 → 候选草稿 → 用户明确采用 → 保留来源”的契约；W7-B 不实现、不宣称、不迁移该能力。

## 6. 保存、取消和成功跳转

- 每页只保留一个主要“保存客户”提交按钮。
- 移除“保存并创建提案”第二个提交按钮；报价/提案继续由客户详情页的次级业务动作承担，本任务不修改报价页面。
- 新建成功：进入 `/clients/{id}`，显示短暂“已创建”反馈。
- 编辑成功：留在 `/clients/{id}/edit`，显示短暂“已保存”反馈。
- 每页提供一个明确取消入口；取消只导航，不写入客户、不写成功审计、不清理不属于本任务的共享草稿机制。
- 页头返回链接与底部取消可以有不同语义，但不得形成两个同等级主要保存操作；批次视觉回归检查其层级权重。

### 6.1 `returnTo` 白名单

保存和取消都携带经过校验的内部 `returnTo`。校验必须解析 URL，而不是仅使用 `startsWith("/")`。

允许：

- `/clients`，仅保留 `q`、`stage`、`purpose`、`temperature`、`sort`、`page`；
- `/organize-center?type=client`，仅保留已批准的查询参数；
- 当前客户编辑页允许回 `/clients/{id}`，其中 `{id}` 必须等于正在编辑的客户 ID；
- `/import-center` 不属于 W7-B `returnTo` 白名单。它是独立 Wizard，其新建/追加/归属流程不得通过客户 Responsive Form 倒灌导航契约。

拒绝并回退安全默认路径：

- 外部绝对地址、协议相对地址；
- `/%5c`、`/\\` 等路径穿越或反斜杠变体；
- 其他来源、未批准 pathname、其他客户 ID、未知查询参数和损坏 URL。

安全默认路径：新建回 `/clients`，编辑回当前客户 `/clients/{id}`。列表筛选、页码、滚动和触发链接焦点恢复属于运行回归；URL 参数必须在代码契约中保留。

## 7. 统一错误契约

创建和编辑共享服务端解析、校验和结构化错误状态；保留 `createClient` 对 `/clients` 范围外快速创建的兼容包装，不复制第二套客户保存逻辑。

校验失败时：

1. 不写客户数据、不写成功审计、不跳转成功页；
2. 保留用户已经输入的全部表单值；
3. 页面顶部渲染唯一错误摘要，使用可编程聚焦元素和 `role="alert"`；
4. 错误摘要获得焦点；每条错误可链接至对应字段；
5. 字段设置 `aria-invalid="true"`，并通过 `aria-describedby` 关联字段错误；
6. 用户激活摘要链接后，焦点进入对应输入；
7. 只有一个 submit，IME 组合态 Enter 不触发误提交的代码机制可以复用，但真实 Kotoeri 结果只能进入批次回归。

Not Found、权限拒绝和租户拒绝继续使用现有边界，不伪装成字段错误。

## 8. 审计原子性风险

当前创建/更新链路是业务写入后再写审计。若审计写入失败，可能出现业务记录已改变但没有成功反馈或完整审计的部分失败状态。

该问题必须在 Checkpoint B/C 风险登记中如实保留，但 TASK-032 不扩展为数据库事务重构、不修改数据库或审计平台，也不得声称已经解决。实现只能复用现有保存和审计调用边界。

## 9. Responsive Form 结构和操作层级

- 页面身份：标题、来源返回和短暂成功/错误反馈。
- 表单主体：以上五个连续业务分组，普通字段使用网格、留白和轻分隔，不为每个字段建立完整卡片。
- 桌面：基本信息和需求条件可使用两至三列；合同与法定信息按标签长度自然分列。
- 768px：压缩为两列或自然重排，保证标签、单位、错误和长文本可读。
- 390px：单列顺序与业务阅读顺序一致，不使用固定最小宽度或横向滚动表格。
- 底部稳定操作区：取消和保存；保存是唯一主要动作，取消是明确放弃编辑的次级动作。
- 不添加完成度、进度条、章节状态徽章、AI 状态、输出入口、跟进历史、报价按钮或第二详情。
- 复用 Layout System V1、TASK-024 Responsive Form 的层级、间距、焦点和错误语言；不新增页面专属颜色、字体、圆角、阴影、焦点或状态 Token。

## 10. 创建与编辑的控制器差异

共享：

- 字段组合、分组、标签、默认值显示规则、解析校验、错误摘要和字段错误语言；
- 单一保存/取消操作层级；
- 租户会话、`record.update` 权限、owner 检查、现有 `addClient`/`updateClient` 和审计调用。

创建控制器保留：

- 无对象 ID 的初始表单；
- `stage=lead` 的初始值；
- 新建成功进入详情并反馈 `created`；
- `/clients` 快速创建兼容包装不被破坏。

编辑控制器保留：

- 按 `clientId + tenantId` 读取对象；
- 缺失或非法枚举拒绝，不回落创建默认值；
- 成功留在编辑页并反馈 `updated`；
- 当前客户 ID 的 `returnTo` 约束。

“姓名必填＋至少一种联系方式”是否比当前“姓名和电话均必填”更符合日本线索来源，属于未来领域模型/产品研究问题。本任务继续电话必填以兼容当前数据库和 Action，不创建新任务、不修改数据库，也不把该长期问题写成当前实现失败。
