## 1. 目标与边界

`/import-center` 使用一个统一 Wizard 外壳，外壳内包含两条有限、明确的业务路径：

- 路径 A：案件资料读取；
- 路径 B：Excel 批量台账导入。

这不是两个产品，也不是把所有来源强制压成同一组线性步骤。路径只在需要不同业务决策时分开；上传、处理状态、返回、刷新恢复、失败反馈和结果摘要由同一 Wizard 外壳承载。

本规格只定义页面结构、状态表达、操作顺序、复用边界和实现停止条件。它不修改或重新定义：

- AI/OCR 算法、第三方文档读取器、422/503 服务端判定；
- 数据库、资料模型、案件模型、权限、Clerk、租户隔离或 API 契约；
- 现有保存、确认事实、来源关联、合并历史、修正事件和审计权威；
- TASK-020、案件详情、输出中心、申请书预览/下载、模板或 `/properties`。

Checkpoint B 的规格不代表真实浏览器、OCR、422 恢复、响应式、键盘、权限或租户体验已通过。

## 2. 统一 Wizard 外壳

### 2.1 进入方式

默认 `/import-center` 首屏只回答：

> 这次要让系统读取什么资料？

首屏结构固定为：

1. 页面身份和当前工作区上下文；
2. 主入口“案件资料”；
3. 次入口“Excel 批量台账”；
4. 已知 `targetCaseId` 时显示已确定的目标案件；
5. 最近导入记录作为次级恢复入口；
6. “没有资料文件？改为手动创建”次级链接，保留现有新建案件、主体和物件路由，但不与上传并列为同级主操作；
7. 高级映射、历史、附件和运维信息折叠在次级区域。

查询参数只用于恢复或聚焦已有流程，不改变两个路径的业务权威：

| 参数 | 页面用途 | 不得推导 |
|---|---|---|
| `xlsxJob` | 恢复 input-file extraction 任务；任务可能来自身份资料或业务文件 | 不等于 Excel 批量台账，也不代表已写入 |
| `job` | 定位通用导入记录；是否进入批量映射由任务类型与 `advanced=1` 共同决定 | 不得仅凭参数名称决定路径、案件形成或已写入 |
| `targetCaseId` | 恢复明确的案件追加上下文 | 不得改成主体/物件归属权威 |
| `intake=existing` | 表达既有案件进入意图 | 不单独证明目标案件，也不得绕过目标读取 |
| `advanced=1` | 展开批量映射/运维区域 | 不得把高级区域变成默认首屏 |

Wizard 路径必须依据现有任务 payload、`sourceType` 和处理结果判断；参数名称只用于定位或展开上下文，不能单独决定进入案件资料路径还是 Excel 批量路径。

### 2.2 外壳固定区域

- 页面标题和当前路径名称；
- 当前步骤指示及可返回的上一步入口；
- 当前任务标识、资料名称和处理状态；
- 一处主要前进/确认操作；
- 错误或异常的可恢复反馈；
- 最近导入记录入口，供离开处理中页面后的恢复使用。

外壳不拥有案件、主体、物件或台账的数据权威，不建立新的全局状态模型。步骤状态应由现有查询参数、任务记录、处理状态、动作结果和保存结果组合表达。

## 3. 路径 A：案件资料读取

### 3.1 步骤和进入条件

| 步骤 | 进入条件 | 用户目标 | 主要操作 |
|---|---|---|---|
| A1 选择资料与进入上下文 | 从默认入口进入，或通过 `targetCaseId`/`intake=existing` 进入 | 说明要读取的资料，并确定是否已有案件上下文 | 选择 PDF/图片等资料、确认既有案件上下文或继续通用入口 |
| A2 上传和系统处理 | A1 已选择资料 | 让系统接收资料并处理 | 上传；查看 `queued`/`processing`/可继续结果；安全返回 |
| A3 只处理异常 | 任务已有识别结果或需要人工处理 | 只处理无法可靠决定的内容 | 修正缺失/冲突/格式/目标问题；按需查看来源、候选和历史 |
| A4 确认保存目标 | 识别结果可继续，且异常已处理或明确保留 | 确定资料写入哪一个案件 | 确认并追加、确认并新建，或确认并合并到所选候选 |
| A5 确认导入结果 | A4 的现有保存动作返回结果 | 判断本次资料是否已进入目标案件 | 查看结果摘要；进入案件，或在无案件落点时回到导入/整理入口 |

### 3.2 目标案件语义

- 从既有案件进入时，`targetCaseId` 已在上传前确定。A1 显示目标案件名称和返回路径；A4 不再让用户重新选择另一个案件，只提供安全返回和明确的“确认并追加到当前案件”。
- 从通用入口进入时，A1 不把“新开案件”伪装成上传前的第三个主入口。识别后在 A4 显示“确认并新建案件”或“合并到候选案件”。
- 合并候选必须显示候选依据、冲突和用户将承担的目标；候选算法只是建议，不能被 UI 表达成自动归属。
- 正常识别字段不逐字段要求用户点击确认，但也不得后台静默写入。A4 必须执行一次对象级明确操作，并复用现有保存、确认事实、来源关联、合并历史、修正事件和审计逻辑。

### 3.3 各步骤显示与隐藏

| 步骤 | 默认显示 | 按需展开 | 默认隐藏或禁止 |
|---|---|---|---|
| A1 | 资料类型、选择/上传控件、既有案件上下文、返回 | 最近记录、资料限制说明 | 与上传并列的主体/物件创建卡片 |
| A2 | 资料名、已收到/处理中状态、任务标识、预计下一步 | 原始任务详情、request ID | 置信度、候选值和逐字段审核列表 |
| A3 | 仅异常数量、异常字段、处理入口和必要说明 | 来源、候选值、置信度、历史、原始资料 | 正常字段常驻任务队列、常驻置信度、逐字段确认要求 |
| A4 | 目标案件、候选依据、冲突摘要、一个明确确认动作 | 合并历史和来源关联摘要 | 自动采用、无依据的“推荐目标”写入 |
| A5 | 资料名、处理结果、保存目标、已写入/未写入/待处理摘要、一个主要下一步 | request ID、审计和原始任务详情 | 从 `mapped`/`completed` 推导案件完整或可输出 |

## 4. 路径 B：Excel 批量台账导入

### 4.1 步骤和进入条件

| 步骤 | 进入条件 | 用户目标 | 主要操作 |
|---|---|---|---|
| B1 上传 Excel | 从首屏选择 Excel，或通过 `xlsxJob` 恢复 | 送入一个批量台账文件 | 选择 `.xlsx` 并上传 |
| B2 确认字段映射 | 工作簿已读取并可展示映射 | 确认列与目标字段关系 | 查看/修正映射；处理未知目标和必填映射 |
| B3 处理数据异常 | 映射可校验，存在必填、格式或行级问题 | 只处理阻塞批量导入的问题 | 修正映射或数据问题；查看错误行、附件和历史 |
| B4 确认批量导入 | 映射和阻塞异常已处理 | 明确执行本次批量写入 | 点击“确认批量导入”，复用现有批量动作和审计 |
| B5 导入摘要 | 批量动作返回结果 | 判断导入结果并继续工作 | 查看成功/跳过/失败摘要；进入整理信息 |

Excel 的字段映射是批量台账的领域步骤，不进入案件资料 OCR 的 A3，也不要求身份证明或扫描资料经过映射界面。B5 的主要下一步固定为进入整理信息；若现有动作只返回部分结果，必须如实显示已写入、未写入和待处理，不补造完成算法。

## 5. 前进、返回、刷新和恢复

### 前进

- 每一步只有一个主要前进或确认动作；辅助动作必须降低视觉权重。
- 前进只在当前步骤的现有校验和权威结果满足时可用。
- 上传成功只表示任务已进入处理队列，不表示案件或台账已写入。
- A4、B4 是对象级明确写入操作；点击后必须禁用重复提交，等待现有动作结果。

### 返回

- Wizard 允许返回上一步；返回不重复上传、不重复触发保存、不清空已有任务。
- 已确定 `targetCaseId` 的 A 路径返回 A1 时保留目标案件上下文；不把返回变成重新选目标案件。
- 处理中返回导入入口或离开页面时，任务继续由队列处理；最近导入记录必须能够恢复。
- 从 A5/B5 进入案件或整理信息后，浏览器返回回到可恢复的导入上下文，而不是再次提交保存。

### 刷新和恢复

- `xlsxJob` 恢复 input-file extraction 任务；`job` 定位通用导入记录。页面根据任务 payload、`sourceType`、处理结果以及 `advanced=1` 判断是否进入批量映射；不能按参数名称直接分流。
- `targetCaseId` 恢复明确的案件追加上下文；`intake=existing` 只表达既有案件进入意图，不单独证明目标案件；`advanced=1` 展开批量映射/运维区域。
- 刷新不得根据 URL 参数单独伪造 `completed`、已写入或可输出状态；必须重新读取现有任务/保存结果。
- 任务不存在时转入“记录不存在”恢复动作，不重复轮询或重复上传。
- 处理中的任务必须在最近导入记录中可继续；已失败任务保留 request ID 和恢复动作。

## 6. 状态契约

页面必须区分以下六类用户事实：

| 用户状态 | 现有事实来源 | 用户可见表达 | 不得推导 |
|---|---|---|---|
| 已收到资料 | 上传动作返回 `jobId`/`requestId` | 资料已收到，正在进入处理 | 不得表示已读取或已写入 |
| 系统处理中 | `queued`/`processing` | 系统正在处理，可离开后从最近记录继续 | 不得表示失败或完成 |
| 需要用户处理 | 现有错误摘要、异常字段、映射/校验结果或未决目标 | 指出具体异常和处理入口 | 不得把正常字段放入默认队列 |
| 读取完成、等待确认 | 可展示识别/映射结果，但尚未执行对象级确认 | 结果已读取，请确认保存目标或批量导入 | 不得表示已写入 |
| 已写入具体案件或台账 | 现有保存/批量动作成功结果、目标 ID、成功摘要 | 明确显示写入目标和写入结果 | 不得由 `mapped`/`completed` 单独推导 |
| 本次导入完成 | 结果摘要已形成，且已有主要下一步 | 显示已写入、未写入、待处理和下一步 | 不得表示案件完整、可输出或主体/物件已归属 |

`mapped` 和 `completed` 只能表达处理/映射层状态。案件完整度、输出资格、主体/物件归属和案件级确认仍由各自权威决定，不能从导入状态推导。

## 7. 错误和恢复动作矩阵

422 不等于全部可人工恢复。UI 必须依据现有 API 返回的错误代码、错误类别或动作语义分类；如果现有返回无法区分，Checkpoint B 的实现前置阻塞应被记录，不能自行创建新的服务端判定。

| 错误类型 | 页面表达 | 用户动作 | 是否允许直接重试 |
|---|---|---|---|
| 内容、格式或映射问题 | 指出资料、列、字段或错误行 | 修正后继续 | 否，先修正 |
| 不支持的文件或来源 | 说明支持边界 | 更换资料或来源 | 否 |
| 可安全重试的处理失败 | 说明失败范围，保留任务和 request ID | 点击重试 | 是，仅现有语义明确允许时 |
| HTTP 422 | 按现有错误代码进一步分类 | 内容/映射问题修正，或按现有恢复动作处理 | 不得统一重试 |
| HTTP 503 处理服务不可用 | 说明服务暂时不可用 | 稍后再试；保留任务和 request ID | 不自动循环 |
| 权限或会话问题 | 不泄露对象存在性 | 返回安全入口或重新登录 | 否，先恢复会话/权限 |
| 记录不存在 | 说明任务已不可用 | 返回导入入口；必要时重新选择资料 | 否，不重复轮询 |

错误反馈必须区分内容、权限、服务和记录状态；不能把所有失败都显示为“重新读取”。

## 8. 确认语义和写入边界

### 案件资料

- 既有案件：`确认并追加到当前案件`；目标在上传前已确定。
- 通用入口新建：`确认并新建案件`；写入成功后显示新案件 ID/入口。
- 合并候选：用户选择候选后执行 `确认并合并到所选案件`；展示依据、冲突和结果。
- 任何确认动作都必须使用既有保存、确认事实、来源任务关联、合并历史、修正事件和审计记录。

### Excel 台账

- B4 使用 `确认批量导入`；映射校验和异常修正完成后才允许执行。
- 批量结果必须显示成功、跳过、失败、未写入和待处理摘要；主要下一步进入整理信息。

“正常字段不逐项确认”只改变默认展示和用户劳动，不授权后台静默写入，也不授权新建第二套保存或确认系统。如果现有动作无法批量采用可读字段，必须在实现前报告技术缺口。

## 9. 响应式结构原则

### 1440 桌面

- Wizard 主内容保持单一阅读顺序；资料/步骤内容为主，任务状态和恢复信息为次级区域。
- 足够宽时可采用主内容与上下文侧栏，但侧栏不得重复主要确认操作或遮挡主内容。
- 异常详情、合并依据和结果摘要保持可扫描，长错误和中日韩文本允许换行。

### 768 平板

- 主内容和上下文区域重排为可读的上下顺序或窄侧栏；不依赖横向滚动。
- 当前步骤、主要操作和异常处理入口保持在首屏可发现范围；次级历史/运维区折叠。
- 文件选择、映射表和错误行允许换行或分组，不压缩成不可读的桌面副本。

### 390 手机

- 单列结构；路径选择、资料控件、状态、异常和确认动作按时间顺序排列。
- 主要操作全宽或足够宽，错误说明、目标案件名、合并依据和按钮正常换行。
- 高级映射、历史、附件和 request ID 默认折叠；不得依赖横向滚动完成上传、修正或确认。

三种视口的结构目标是保留任务顺序和动作可达性，不是像素复制；本规格不宣称浏览器响应式已通过。

## 10. 键盘与焦点顺序

- 页面进入后焦点落在页面标题或当前步骤标题；恢复任务时聚焦当前恢复状态，而不是重新聚焦首屏上传控件。
- 首屏顺序：路径入口 → 资料选择/文件控件 → 当前步骤主要操作 → 最近记录/手动创建次级链接。
- A3 异常顺序：异常摘要 → 第一个需要处理的异常 → 按需展开来源/候选/历史 → 下一步确认。
- B2/B3 顺序：映射表或错误行 → 修正控件 → 校验反馈 → 确认批量导入。
- 上传控件必须保持真实可聚焦的 input/button 语义；不使用仅靠 `div` 点击的伪控件。
- 步骤前进后，焦点移到新步骤标题或首个可操作控件；返回后恢复返回来源步骤的标题或触发控件。
- 处理失败后焦点进入可感知的错误区域或第一个可恢复动作；503 不自动循环抢焦点。
- A4/B4 提交后禁用重复提交；成功后焦点移到结果摘要标题，失败后移到错误反馈。
- 键盘、焦点恢复、组合输入和屏幕阅读器行为均需在后续实现验收中取得证据；当前未验证。
