## 0. 目标和停止边界

目标是让用户找到一个个人或法人主体，读取真实保存的身份、联系方式、生命周期和角色，并进入正确的主体维护动作。`/parties` 是单一主体 List Report，不是客户跟进看板、案件完成度面板、输出资格检查器或第二套主体详情页。

本轮只提交目标结构规格并同步治理文档。不得修改 `src/`，不得启动服务、实现 Agent 或审查 Agent，不得修改主体数据、数据库、API、权限、认证、租户、输出专题或 `src/app/clients/page 2.tsx`。

## 一、对象和术语边界

- 用户界面对象继续称为“主体”。
- 当前持久化权威仍是 `Client` 记录；本任务不新增主体表、不迁移数据库。
- 这是兼容数据实现，不得在规范、界面或状态文案中宣称“客户等于主体”。
- 客户的阶段、用途、温度、报价和跟进模型不得进入主体列表。
- 是否建立独立主体事实层留作未来领域模型任务，不纳入 W6-B。
- `/parties` 的列表事实只从现有主体适配层读取；列表不能把页面推断升级为领域事实。

## 二、权威字段契约

### 2.1 默认列表允许字段

默认结果行只允许显示：

1. 主体名称；
2. 明确保存的个人/法人类型；
3. 明确保存的主体角色；
4. 电话或邮箱摘要；
5. 生命周期状态；
6. 为维护动作服务的次级操作入口。

结果数量是当前查询结果的结构性计数，不是完成度、业务 KPI 或输出进度。

### 2.2 来源规则

- 类型和角色只认可主体档案元数据中的显式值。
- 缺少显式元数据时显示“未设置”，不得显示猜测值。
- 禁止使用名称、`purpose`、`stage` 推断类型或角色。
- `preferredArea` 不得显示为“关联物件”，也不得作为关系事实或完成度输入。
- quotation/contract 数不得显示为案件数量，也不得作为“有关联/无关联”筛选依据。
- 不显示主体完成度、案件完成度、输出资格、AI 状态或任何“已准备好”推导。
- 正常主体字段静默展示；只有生命周期异常或操作失败才使用突出状态语言。

若实现需要区分显式值与旧记录兼容推断，可在现有页面适配层或 `src/lib/hub.ts` 暴露来源标记。来源标记只用于保证显式值优先和缺失值显示“未设置”，不得修改数据库或另建业务模型；兼容推断不得回到默认列表展示。

## 三、页面结构

### 3.1 页面骨架

采用标准 List Report，页面顺序固定为：

1. 页面标题、当前查询结果数量和“新增主体”主操作；
2. Filter Bar；
3. 结果区；
4. 空结果或无主体状态；
5. 分页与返回上下文。

桌面端仍是一个列表工作区，不建立右侧详情栏。手机端使用单列结果行，不能把桌面多列压缩成横向溢出表格。

### 3.2 Filter Bar

Filter Bar 只包含：

- 搜索；
- 个人/法人；
- 生命周期；
- 清除筛选。

不得保留“有案件/无案件”筛选。当前没有权威案件关系来源，不能以 quotation/contract 计数替代该筛选。

### 3.3 结果行

结果行按固定层级显示：

- 主体名称；
- 类型；
- 角色；
- 联系方式摘要；
- 生命周期；
- 行尾次级操作。

主体名称是唯一主要进入链接。行尾箭头不得成为重复 Tab 停靠点；不得为同一编辑动作增加第二个整行或箭头链接。

### 3.4 明确移除的现有结构

目标结构不得保留：

- `focus` 选中模型；
- URL 无 `focus` 时默认选中第一条；
- 右侧完整详情面板；
- 完成度、进度条和 `complete/insufficient` 徽章；
- “有案件/无案件”筛选；
- 关联案件数；
- “输出前检查”；
- 创建案件、打开案件或 quotation 路由；
- 输出中心资料入口；
- 附件列表；
- 在列表中重复提供编辑和归档操作的第二套详情入口。

关系图不是列表详情替代品，只作为行级次级入口保留。主体详情和编辑工作继续由现有 `/parties/[id]/edit` 承担，本任务不迁移该页面。

### 3.5 状态和空态

- 有结果：仅显示权威字段和当前行操作。
- 有筛选但无结果：说明当前筛选没有匹配主体，并提供清除筛选。
- 无主体：说明当前租户暂无主体，并提供“新增主体”主操作。
- 加载：复用现有 List Report 加载语言，不展示伪进度或临时完成度。
- 读取错误：显示诚实的读取失败说明、重试和安全返回；不得把错误改写成“无主体”。
- 归档/恢复或其他操作失败：在当前列表上下文中说明失败，保留用户的筛选和页码条件。

## 四、操作层级

- “新增主体”是页面级主操作。
- 主体名称是唯一主要进入链接，进入现有 `/parties/[id]/edit`。
- 关系图作为行级次级入口，进入现有 `/relationship-tree`；不在列表中内嵌关系图或详情。
- 归档/恢复是风险操作，放入稳定、可识别的次级操作位置，并继续使用现有生命周期权限、审计和安全返回能力。
- 不建立整行 selected 状态，不因点击主体名称改变列表上下文中的隐式详情状态。
- 行尾箭头不得成为重复 Tab 停靠点；只有实际不同的目的地才可成为独立链接。
- 编辑页的产品内返回路径属于 W7。本任务至少要求主体名称链接使用可回放的列表 URL，使浏览器历史返回能够恢复列表上下文和触发主体链接焦点；不能依赖旧 `focus` 参数恢复右侧对象。

## 六、筛选和返回契约

### 6.1 URL 参数

列表 URL 只保存：

- `q`：搜索词；
- `type`：个人/法人；
- `lifecycle`：生命周期筛选；
- `page`：页码。

`q`、`type`、`lifecycle`、`page` 是列表筛选和分页的 URL 权威参数。`flash` 允许作为创建、更新、归档或恢复后的短暂操作反馈参数，但不是筛选、选中对象或业务状态；不得将其用于驱动列表结构或主体详情。新结构不得产生或依赖 `focus`、`relation` 作为主体选中或关联案件状态。旧 URL 中存在 `focus` 时不得恢复右侧对象或默认替换成第一条；实现应忽略或安全清理该参数，并保持其他合法筛选条件。

### 6.2 历史返回

浏览器历史返回必须恢复：

- 搜索、类型和生命周期筛选；
- 当前页码；
- 列表滚动位置；
- 触发主体链接的焦点。

不得恢复：

- 旧 `focus` 选中对象；
- 右侧详情状态；
- 输出检查、案件动作或附件展开状态。

浏览器历史返回不要求恢复旧 `flash`；反馈可以在返回后自然消失，不得因此丢失合法的筛选、分页或列表上下文。

归档/恢复后的安全返回应尽量保留当前筛选、页码和安全 `returnTo`。如果现有动作无法支持，Checkpoint C 必须报告具体缺口，不能静默重置或扩大修改范围。

若当前数据源尚不支持权威分页，Checkpoint C 不得自行制造业务分页计数；应明确报告数据源缺口，并只实现已存在的分页契约。
