# TASK-030 / W6-C：物件索引 `/properties` List Report 目标结构规格

- 规格状态：Checkpoint B 方向批准；有限事实修正已纳入，授权进入 Checkpoint C
- 任务状态：`In Progress`
- 本规格只保留一个标准 List Report 方案；事实修正完成后只进行一次有限实现
- 依据：TASK-030 Checkpoint A 只读审计及产品负责人复审结论

## 0. 目标与停止边界

`/properties` 的唯一核心任务是：让用户快速找到一个物件，读取系统真实保存的名称、区域、价格费用和生命周期，并进入正确的物件维护动作。页面是标准 List Report，不是台账仪表盘、输出准备度看板、关系摘要页、活动时间线或第二套物件详情。

本轮先修正 area 数据链、空值/lifecycle 规则并同步治理文档，随后按本规格授权一次有限实现。不得修改数据库结构、migration、actions、API、认证、权限、租户或物件数据，不启动服务，不重新进行方案讨论。未跟踪的 `src/app/clients/page 2.tsx` 保持原状、未提交、未删除。

## 一、对象、来源与字段契约

### 1.1 持久化边界

- 当前列表权威来自现有 `properties` 记录及其 `listQuoteFormData` 适配路径；本任务不新增物件表、不迁移数据库、不重写数据模型。
- 当前 `listQuoteFormData` 的 memory/PostgreSQL properties 列表适配尚未返回 `area`，因此只修改 `hub.ts` 不足以得到真实区域。Checkpoint C 额外允许在 `src/lib/data.memory.ts` 和 `src/lib/data.postgres.ts` 的该列表映射中补回已保存的 `area`，并以有限契约测试证明两条适配路径一致；不得借此修改其他查询、保存逻辑或页面。
- 修正后 `listHubProperties` 只读取适配结果中的真实 `area`，不再从名称推断；页面列名与说明使用“区域／エリア”等对应语言，不把 `area` 写成“所在地”，也不新增完整 `address` 列。
- `properties.lifecycle_status` 已有仓库级迁移契约：`db/migrations/20260808_001_record_lifecycle.sql` 为 `properties` 增加生命周期、归档时间、归档人字段及租户/生命周期索引。因此 lifecycle 可以进入目标结构；当前目标数据库是否已完整应用该 migration 没有运行证据，必须进入批次回归，不得在页面中宣称已验证。
- 当前列表数据契约没有可用的 `updatedAt`。不得用 ID、创建顺序或其他排序替代更新时间；“最近更新”排序冻结，直到另立任务提供权威字段契约。

### 1.2 默认列表允许字段

结果区默认只允许显示：

1. 物件名称；
2. 真实保存的 area/区域；
3. listing price；
4. management fee；
5. repair fee；
6. lifecycle；
7. 归档/恢复等必要的次级风险操作。

物件名称是唯一主要进入链接，进入现有物件维护页面。不得为同一维护动作增加整行链接、行尾重复箭头或第二个主要 Tab 停靠点。

### 1.3 空值与来源规则

- area 必须来自真实保存的 `area` 字段；不得再从物件名称是否包含“区”推断区域。缺失时显示诚实的“未设置”或等价空值文案。
- `managementFee`、`repairFee` 当前能够保留 `null`；空值显示“未设置”，真实 `0` 显示零值。
- `listingPrice` 在持久化模型中是必需数字，但正常新建动作可能把空输入保存为 `0`，编辑页也把非正数视为未填写。列表将 `listingPrice <= 0` 显示为“未设置”；价格降序时无有效价格的记录排在有效价格之后，不改变持久化数据，也不宣称数据库区分 listing price 的 `null` 与 `0`。
- 若共享 `HubPropertyItem` 为既有页面保留数值兼容字段，必须同时暴露仅供本 List Report 使用的原始 nullable 费用值；`/properties` 只读取原始值，不能把兼容性投影当作权威空值语义，也不得扩展为新的业务模型。
- 附件集合是真实来源，但当前读取存在上限，附件计数可能低估；因此附件数不作为默认列，也不得推导资料完整度、输出准备度或任何完成算法。
- owner、物件类型、关联主体、关系、活动和更新时间没有可靠的列表契约，全部不展示。
- lifecycle migration 契约为 `NOT NULL DEFAULT active`，正常业务值只有 `active` 和 `archived`。页面只显示这两个值；如果目标数据库未应用 migration 导致读取失败，应进入错误状态，不把缺少字段解释成某条物件的第三种生命周期。

### 1.4 明确禁止的非权威表达

目标列表不得保留或重新生成：

- 固定价格趋势、价格变化百分比或总价乘固定系数；
- “可输出”“输出准备”“资料完整度”及字段非空比例；
- active 数量等于“可输出物件”；
- active 比例或固定百分比等于资料构成；
- 行级准备度、必填完成度、AI 状态或其他新算法；
- 循环或随机 Unsplash 封面图，或任何不来自物件资料的图片；
- 通过 `preferredArea`、名称字符串或其他模糊匹配制造主体/物件关系；
- 静态活动时间线、虚构最近更新时间或创建顺序冒充业务事件；
- `focus`、默认选中第一条、右侧详情面板或列表内第二套物件详情；
- 汇总 KPI、底部圆图/仪表盘、输出中心入口和案件动作。

## 二、页面任务与 Floorplan

页面从上到下只有一个结果工作区：

1. 页面身份：标题“物件”和一段简短说明；唯一主要操作“新增物件”，进入现有 `/properties/new`。
2. Filter Bar：关键词 `q`、生命周期 `lifecycle`、排序 `sort`、清除筛选。
3. 结果区：结果数量、标准列表列标题和结果行；桌面为列结构，手机为连续单列信息行。
4. 空结果、无物件、加载或读取错误状态。
5. 分页和返回上下文。

页面头部不保留列表内姓名式快速创建表单或 `FormDraftAssist`。后端 `createPropertyQuickAction` 不删除、不修改，但本页不再调用；`/properties/new` 是唯一主要新建路径。

不得把每个物件渲染为相互竞争的卡片，不建立右侧选中对象、不显示底部统计区、不在列表中放置输出、关系或活动工作台。

## 三、筛选、排序与 URL 契约

### 3.1 权威 URL 参数

列表 URL 只保存以下筛选/分页参数：

- `q`：按物件名称和真实保存的 area/区域搜索；不得搜索页面虚构的关系或类型。
- `lifecycle`：生命周期筛选；值来自现有保存的 lifecycle 契约。
- `sort`：只允许默认顺序和价格从高到低。
- `page`：页码。

默认顺序不宣称“最近更新”。`sort=price` 只能表达已有价格值的降序排列，不能伪装成价格筛选、趋势或价值变化。

### 3.2 明确不提供的筛选

不得提供：

- 没有权威字段来源的物件类型筛选；
- 伪装成价格筛选的排序链接或价格区间控件；
- “最近更新”排序；
- 输出准备度、资料完整度、关系状态、主体或活动筛选。

清除筛选只清除 `q`、`lifecycle`、`sort` 和 `page` 的列表条件，不恢复旧 `focus` 或任何侧栏状态。

### 3.3 历史返回

物件名称链接应携带可回放的列表上下文，使浏览器返回尽量恢复：

- `q`、`lifecycle`、`sort` 和 `page`；
- 列表滚动位置；
- 触发物件链接的焦点。

旧链接中存在 `focus` 时可以兼容忽略或安全清理，但不得重新建立 selected 模型、默认选中第一条或右侧详情。若现有编辑页/归档动作无法保留筛选和页码，Checkpoint C 必须报告具体缺口，不能静默扩大修改范围。

## 四、操作层级与边界

### 4.1 创建、维护与归档

- “新增物件”是页面唯一主要操作，进入 `/properties/new`。
- 物件名称是结果行唯一主要维护入口，进入现有物件编辑页；本任务不迁移编辑页。
- 归档/恢复是风险操作，位于稳定的次级操作位置，复用现有 lifecycle、权限、安全返回和审计事实。
- 不在列表中调用快速创建，不把“整理物件”、输出或案件动作提升为主要入口。

### 4.2 CSV

- `/properties` 页面移除 checkbox、批量工具和导出按钮；不显示“暂不可用”占位控件。
- 不修改、不删除现有 `/api/hub/export?scope=properties`；其字段契约、空选择行为、权限、租户范围和审计风险另行记录，不在 W6-C 修复。
- 页面不得触发空 `ids` 导出全部物件，也不得宣称导出当前筛选结果或全部物件。
- 如未来恢复物件导出，必须另立任务确定权威字段、空选择、筛选范围、权限和审计。

### 4.3 关系与输出

- `/relationship-tree` 只保留为现有系统的独立入口核对项，不进入本列表；任何名称/area/preferredArea 字符串匹配都不是关系事实。
- `/output-center`、预览、下载、版权、售卖和“输出准备”继续属于冻结的独立输出专题；本页面不提供资料入口、输出检查或下一步输出文案。

## 五、状态、空态和错误

- 加载：显示真实的列表加载状态，不显示伪进度、KPI 或完成比例。
- 有结果：安静显示允许字段；正常 lifecycle 不堆叠徽章，归档状态可使用适度状态语言。
- 有筛选但无结果：说明当前条件没有匹配物件，并提供清除筛选；不重复提供“新增物件”作为第二个页面级主要按钮。
- 无物件：说明当前租户暂无物件；保留页面头部的“新增物件”主要操作，空态只作说明，避免重复主操作。
- 读取错误：显示诚实的读取失败说明和安全重试/返回动作；不得把读取错误改写成空列表。
- 归档/恢复失败：保留当前筛选、排序和页码，说明操作失败；不得伪称生命周期已更新。
- lifecycle 只能显示 `active` 或 `archived`；若 migration 缺失造成列表读取错误，显示错误态，不补造第三种业务状态。

## 六、响应式结构

- 1440px：使用标准 List Report 列结构，列标题与结果行对齐；不出现 KPI、卡片墙或第二详情。
- 768px：压缩列间距和次要文字，仍保持名称、area、价格费用和 lifecycle 的可读顺序；不以隐藏列制造语义丢失。
- 390px：转为连续单列信息行，使用明确的行内字段标签；主要名称链接和归档/恢复次级操作保持可达。
- 任意宽度均不得使用最小宽度 `1080px` 的横向滚动表格，不以横向溢出替代响应式结构。
- 正常信息安静呈现；仅生命周期异常或操作失败可适度突出，避免每行多个徽章、按钮和卡片竞争。

## 七、键盘与返回上下文

- 页面标题、Filter Bar 控件、清除筛选、新增物件、每个物件名称链接和风险操作必须按视觉任务顺序形成可预测 Tab 顺序。
- 同一物件的名称和行尾箭头不得产生重复主要 Tab 停靠点；没有不同目的地就不增加第二个链接。
- Enter 应激活当前聚焦的原生链接或按钮；归档/恢复仍遵循现有风险确认语义。
- 浏览器返回以 URL 参数和现有页面上下文恢复筛选、排序、页码、滚动和触发链接焦点；不恢复旧 focus、选中对象、侧栏、输出检查或关系展开。
- 本规格不宣称真实 Tab、Enter、返回焦点或完整无障碍运行通过；若当前环境无法取得证据，统一进入全产品迁移后的批次回归。
