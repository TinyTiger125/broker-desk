# MIG-004 日语术语裁决决策材料（草案）

> 状态：仅供产品决策准备，未批准、未Ready、未In Progress。
> 本文件不改变任何界面、代码、翻译、官方表格原文或任务状态。

## 目的和边界

MIG-004只裁决会改变用户理解、业务含义或产品体验的用户可见词。内部变量名、文件名、技术字段、schema、mapping、坐标和文档放置不提交给产品决策；它们由工程按既有规则处理。

同一概念必须先确定业务含义，再确定中文、日文、韩文表达。不能因为三种语言字面相似，就把不同状态合并；也不能因为代码已有字符串，就把历史或当前实现自动升级为规范。

## 裁决顺序

1. 日本官方文书中的正式用语。
2. 日本房地产及保证公司行业惯用表达。
3. 当前产品中用户能够理解的表达。
4. 同一状态在中、日、韩三种语言中的语义一致性。
5. 当前代码实际使用情况。
6. 两份 2026-07-14 历史字典和旧设计资料。

官方和行业资料显示，正式文书会使用 `入居申込書`、`保証委託申込書`、`賃貸保証委託申込書` 等具体名称；国土交通省的租赁资料使用 `貸主`、`借主`、`家賃債務保証業者` 等角色或制度词。UI可以使用较短的 `保証会社`、`申込書`，但不能改写官方表格上的原始栏目和标题。

## 真正需要产品负责人确认的词

只保留以下五组需要确认，因为它们会改变用户对主流程的理解：

1. 首页：`業務資料ハブ` → `資料管理センター`。
2. 首个入口：`作成・資料登録` / `情報入力` → `案件作成・資料読取`，并拆分案件创建与资料读取动作。
3. 案件整理：`情報を整理する` → `案件情報を整理`。
4. V1输出：`文書出力` / `書類を出力` → `申込書を出力`。
5. Party集合名：中文`主体`与日文`関係者`是否统一为中文`关系人`、日文`関係者`、韩文`관계자`，同时保留具体角色名。

其余词按上表推荐直接作为后续实现规则，不需要产品负责人在字典A/B之间二选一。任何实际回填仍须另有任务卡、授权、验证和独立审查。
