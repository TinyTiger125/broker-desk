# Broker Desk 产品核心名词字典

更新日: 2026-07-14
状态: 业务审校草案

## 使用边界

这份字典用于统一产品界面里的概念词、按钮词、状态词和页面说明。

它不用于翻译业务资料原文。人名、地址、楼名、房号、公司名、文件名、官方表格栏目名原则上保留原文。

## 产品一句话

Broker Desk 的 V1 产品逻辑是:

```text
资料进来 -> 只补缺失项 -> 输出申请书
```

界面词汇应该服务这个逻辑。用户不应该感觉自己在配置系统、映射字段、校准模板或管理数据库。

| --- | --- | --- | --- | --- |

## 关键动作词

| 场景 | 建议用词 | 避免用词 | 说明 |
| --- | --- | --- | --- |
| 上传并识别资料 | 读取资料 | 导入文件、字段识别 | `读取`比`导入`更贴近用户想要的结果。 |
| 创建业务作业 | 新建案件 | 创建记录 | 用户做的是业务案件，不是数据库记录。 |
| 创建人员/公司 | 新建关系人 | 新建主体 | 若确认继续使用`主体`，至少避免在按钮中过度出现。 |
| 创建房产对象 | 新建物件 | 新建资产 | `资产`容易偏投资系统。 |
| 继续补资料 | 继续整理 | 继续编辑字段 | 强调完成业务，不强调字段。 |
| 保存确认结果 | 保存确认结果 | 写入标准字段 | 不暴露内部字段模型。 |
| 输出保证公司申请 | 输出申请书 | 生成 PDF | PDF 是格式，不是用户目标。 |
| 回到案件 | 查看案件 / 回到案件 | 打开记录 | 保持业务对象语言。 |

## 状态词

| 状态 | 建议中文 | 使用场景 | 避免混用 |
| --- | --- | --- | --- |
| Ready | 已整理 | 基础资料够用，可以继续关联或输出。 | 不要和`已确认`混用。 |
| Needs work | 待整理 | 这个对象还有明显待处理事项。 | 不要泛化成所有异常。 |
| Missing required fields | 待补全 | 必填项为空，用户需要填写。 | 比`异常`更有行动指向。 |
| Extraction needs review | 待确认 | 系统读到了值，但需要用户确认。 | 不要用于空字段。空字段用`未填写`。 |
| Empty field | 未填写 | 字段没有值。 | 不要写`不明`。 |
| Confirmed by user | 已确认 | 用户明确采用或核对过。 | 不等于`已整理`。 |
| Edited by user | 已修正 | 用户改过系统识别结果。 | 不要写成`已编辑`，后者太泛。 |
| Conflict | 不一致 | 多份资料给出不同值。 | 不要写`错误`，除非已经确认错误。 |
| Not applicable | 不适用 | 该项对当前案件不需要。 | 不等于`不采用`。 |
| Rejected suggestion | 不采用 | 用户明确不采纳系统建议。 | 不等于`不适用`。 |
| Unknown | 无法判断 | 系统或用户无法确定。 | `不明`偏翻译腔，少用。 |

## 字段与输入区用词

| 当前风险词 | 建议替换 | 原因 |
| --- | --- | --- |
| 字段 | 项目 / 填写项目 | `字段`是 IT 语言。 |
| 字段匹配值 | 保存成 / 对应到 | 用户要知道会保存到哪里，不需要知道字段匹配。 |
| 保存项 | 保存成 | 动词更清楚。 |
| 系统判断 | 自动识别结果 / 隐藏 | 这属于内部能力，不需要宣传。 |
| 预览值 | 读取结果 | `预览值`偏技术。 |
| 映射 | 对应 / 保存到 | `映射`不适合普通经纪。 |
| key / ID | 不展示 / 编号 | 除非用户真的需要引用编号。 |
| contract_number | 合同编号 | 绝不直接展示内部字段名。 |

## 第一轮建议重点审校词

这些词最影响朋友的第一眼理解，建议优先在 CSV 里确认:

| 当前词 | 我的建议 | 需要朋友判断的问题 |
| --- | --- | --- |
| 资料管理中心 | 资料管理中心 | 是否比`业务资料中枢`更自然。 |
| 建档入口 | 建档入口 / 读取资料 | 作为导航是否清楚；作为按钮是否应改成`读取资料`。 |
| 整理信息 | 整理信息 | 是否能理解这里是补齐案件资料。 |
| 输出文件 | 输出申请书 | 保证会社主任务下是否更直接。 |
| 主体 | 关系人 / 客户/关系人 | `主体`是否过于抽象。 |
| 待归属资料 | 待归类资料 | 哪个更符合直觉。 |
| 台账 | 列表 | 前台是否减少`台账`出现。 |
| 待确认 | 待确认 | 是否只用于“读到了但没确认”。 |
| 待补全 | 待补全 | 是否用于“空着需要填”。 |
| 无法判断 | 无法判断 | 替代`不明`。 |

## 工程落地规则

1. 如果 CSV 行是 `source=i18n`，审校结果可以自动写回。
2. 如果 CSV 行是 `source=hardcoded`，先迁移到 `src/lib/i18n.ts`，再导入。
3. 审校通过的核心词要同步到本文件，避免后续页面再次发散。
4. 任何新页面不应重新引入 `字段映射`, `系统判断`, `contract_number` 这类普通用户不理解的词。
5. 产品 UI 可以中文化，业务数据原文不中文化。
