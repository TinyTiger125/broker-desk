# Broker Desk 日语用语快速审校说明

更新日: 2026-07-14

## 目的

这次想请你帮忙看一下 Broker Desk 里出现的日语界面文案，判断这些说法在日本不动产经纪业务里是否自然、准确、好理解。

你不需要看代码，也不需要理解技术实现。只需要打开 CSV 表格，在指定的一列里写修改建议。

## 这次只看这一份表

请只看这一份文件：

```text
docs/operations/ui-terminology-ja-starter-review.csv
```

这是一份“快速审校表”，只抽出了最影响第一使用体验的日语界面文案。

这次不需要全量审校，也不需要把所有词都改完。优先看那些你觉得用户第一眼会疑惑、不自然、不像日本房产经纪日常说法的词。

## 怎么打开

可以用 Excel、Numbers 或 Google Sheets 打开。

如果出现乱码，请用 `UTF-8` 编码打开。

## 只改哪一列

只改这一列：

```text
suggested_text
```

`current_text` 是现在产品里显示的日语文案。

如果你觉得 `current_text` 不自然、不准确，或者有更好的说法，就把修改建议写到同一行的 `suggested_text` 里。

如果你觉得这个词没问题，`suggested_text` 留空就可以。

## 不要改哪些列

下面这些列都不要改：

```text
id
surface
source
file
line
occurrences
locale
key
current_text
notes
```

也请尽量不要删除行、增加列、改列名、合并单元格或大幅调整表格结构。这样我后面才能把你的修改安全导回系统。

## 每列大概是什么意思

| 列名 | 含义 |
| --- | --- |
| `current_text` | 当前产品界面上的日语文案。 |
| `suggested_text` | 你建议替换成的新日语文案。只改这一列。 |
| `source` | 系统内部用来判断能不能自动导入。你不用处理。 |
| `file` / `line` | 工程定位用。你不用处理。 |
| `notes` | 工程导入说明。你不用处理。 |

## 你主要帮我判断什么

请重点看这几类问题：

- 这个日语是不是日本不动产经纪业务里自然会说的话。
- 用户第一次看到这个词，能不能知道下一步该点哪里。
- 有没有太像系统语言、IT 语言、开发者语言的表达。
- 按钮名是不是明确，例如用户看了会不会想点。
- 状态名是不是有行动指向，例如看了能不能知道是“需要确认”“还没填写”“已经整理好”。

## 特别想请你注意的词

下面这些词如果你觉得有更自然的说法，可以在表里给建议：

| 可能需要判断的当前说法 | 审校思路 |
| --- | --- |
| `業務資料ハブ` | 作为首页/资料中心名字是否自然。是否应改成 `資料管理センター` 一类更直观的说法。 |
| `作成・資料登録` | 作为入口按钮是否清楚。用户是否知道这里是新建案件和读取资料。 |
| `情報を整理` | 是否能理解这是整理案件资料。是否需要更明确成 `案件情報を整理`。 |
| `書類を出力` | 如果主流程是保证会社申请书，是否 `申込書を出力` 更明确。 |
| `台帳` | 普通用户界面里是否太硬，是否更适合用 `一覧`。 |
| `確認待ち` | 状态名是否自然，是否 `要確認` 更清楚。 |
| `不明` | 是否太短或太模糊，是否 `判断できない` 更好。 |

## 不要翻译或改写的内容

有些内容不是界面文案，而是用户上传资料里的原始信息。这些不要硬翻译，也不要改成中文或另一种日语说法。

例如：

| 类型 | 示例 | 处理方式 |
| --- | --- | --- |
| 人名 | `ガルシア マリア`, `佐藤 健一` | 保留原文。 |
| 地址 | `東京都港区...` | 保留原文。 |
| 物件名 / 建物名 | `港区グランドタワー 8F` | 保留原文。 |
| 公司名 | `Lu Trading合同会社` | 保留原文。 |
| 文件名 | `勝どきリバーサイド_賃貸申込一式.xlsx` | 保留原文。 |
| 官方申请书上的栏目名 | `申込者`, `勤務先`, `緊急連絡先` | 保留官方原文。 |

这次主要审校的是：页面标题、按钮、状态、说明文、操作路径这些“产品界面用语”。

## 占位符不要删

如果文案里出现这种内容，请保留：

```text
{{count}}
{company}
%s
```

例如：

```text
検索結果 {{count}} 件
```

这里的 `{{count}}` 会在系统里自动替换成数字。你可以调整前后文案，但不要删除或改坏这个占位符。

## 填写例子

可以这样填：

| current_text | suggested_text |
| --- | --- |
| 業務資料ハブ | 資料管理センター |
| 作成・資料登録 | 案件作成・資料読取 |
| 書類を出力 | 申込書を出力 |
| 確認待ち | 要確認 |
| 不明 | 判断できない |

如果没问题，就留空：

| current_text | suggested_text |
| --- | --- |
| 物件 |  |
| 関係者 |  |
| 申込書 |  |
| 保証会社 |  |

## 如果拿不准

拿不准的时候不用硬改。

可以留空，或者另外写一句备注，例如：

```text
这个词有点怪，但我暂时想不到更好的说法。
```

这次是快速审校，所以不用追求一次性完美。最重要的是把“第一眼会让真实用户困惑的日语词”先找出来。
