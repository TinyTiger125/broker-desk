# Broker Desk Prelaunch Product Audit - 2026-06-30

## Audit Scope

## Step Health

1. 资料管理首页：健康。当前案件、当前卡点、继续整理、资料追加和下方资料关系模块能形成明确入口。
2. 创建与导入：健康。四类创建/导入入口清晰，上传区能让用户先选择处理对象。
3. 整理中心：基本健康。任务列表、对象类型和当前对象面板逻辑通顺，适合作为批量处理入口。
4. 案件资料地图：健康。按资料树节点深链后能直接定位到对应字段组，用户不会回到页面顶部。
5. 输出中心：健康。选中案件后主行动是预览保证书，缺项和公司别项目都有明确入口。
6. 保证书预览：可用但有一个体验风险。公司确认项能填写并保存，但跳到该区域时左侧 PDF 预览上下文较弱，左侧可见区域接近空白。

## UX Risks

1. 保证书预览页的公司确认项锚点会把用户带到右侧表单区域，但左侧 PDF 预览不够有上下文。
   - 影响：用户知道自己在补字段，但不一定能立刻看到这些字段如何影响表单。
   - 建议：真实测试后优先考虑让 PDF 预览区域保持缩略上下文，或在公司确认项区顶部显示当前保证公司、当前案件和返回预览顶部的快捷入口。

2. 默认语言目前依赖 cookie；没有 cookie 时原始默认是日文。
   - 已处理：新增 `BROKER_DESK_DEFAULT_LOCALE` 环境开关，真实中文测试可用 `zh` 启动。
   - 剩余风险：部分业务名词和日文姓名/地址会保留原文，这是有意设计，不应硬翻译。

3. 整理中心的信息密度仍高。
   - 影响：对熟练用户可用，对首次真实用户可能需要 1-2 分钟建立“左侧类型 -> 中间任务 -> 右侧当前对象”的心智。
   - 建议：真实测试观察是否有人误以为右侧面板是独立详情页；如果发生，再增加更明确的选中态和返回/打开动作。

## Accessibility Risks

1. 当前审计基于截图和静态路由检查，不能证明完整键盘可达性或读屏顺序。
2. 部分按钮和标签使用低字号加粗风格，视觉上可读，但仍需要后续用键盘 Tab 顺序和焦点状态单独验证。
3. 预览页是双栏、长页面、表单密集结构，缩放到较小屏幕时需要单独做响应式检查。

## Product Decision

可以进入朋友真实测试，但应使用空业务数据环境，并建议用中文默认语言启动。当前剩余问题不阻断测试，反而适合在真实测试中观察：用户是否理解整理中心、是否能从输出缺项回到正确的整理位置、是否能在保证书预览里完成公司确认项。
