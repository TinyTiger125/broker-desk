# Broker Desk Layout System V1

- 状态: Draft，等待阶段 A 目标图批准
- 唯一 Layout 规范来源: 本文件
- 适用产品: Broker Desk Web
- 参考: SAP Fiori Object Page、Dynamic Page、List Report、Worklist、Wizard、Preview & Confirmation
- 不采用: SAP 品牌视觉、SAPUI5、Fiori Elements、企业复杂工具栏和无关配置层级

本文件只规定页面结构、操作层级、响应式和无障碍语言，不规定产品业务事实、149 项字段、数据模型、权限、租户、输出门禁或用户可见术语。业务事实继续由现有产品文档、任务卡、字段目录和术语规范提供。

## 1. Layout 原则

1. 先按用户主要任务选择 Floorplan，再选择组件；不先按视觉风格套页面。
2. Shell、Dynamic Page Header、页面标题、操作层级、状态和焦点保持一致；Worklist、List Report、Object Page、Wizard 和 Preview & Confirmation 保留各自任务差异。
3. 正常业务结果安静展示；异常、缺失、错误、输出阻塞和恢复动作才获得视觉强调。
4. 页面级全局操作与字段/行级局部操作分层，不在顶部、底部和局部同时重复同一动作。
5. 只渲染当前任务、角色和对象适用的内容；不把 Layout System 变成 149 项底层字段、AI 证据和历史记录的万能容器。
6. 所有结构变化都必须保留当前业务能力、数据来源、权限、返回路径和异常恢复；视觉统一不能替代业务回归。

## 2. Shell

- 桌面端：全局导航、工作区身份、主内容区域、全局反馈和用户菜单保持稳定层级。
- 平板/手机：导航可以收起，但当前页面身份、返回路径和当前任务必须可见；不以横向压缩桌面 Shell 作为响应式方案。
- 内容区域使用统一的有效宽度、边距、垂直节奏和焦点层级；页面内容不得被固定操作栏遮挡。
- Shell 不拥有领域数据，不在 Shell 内决定案件状态、模板状态或权限结果。

## 3. Dynamic Page Header

- 顶部展开态显示页面/对象身份、关键业务状态和页面级主要操作。
- 向下滚动后压缩，仍保留最小身份、当前上下文和必要全局操作；不能让用户不知道正在查看哪个案件或对象。
- 主要操作只保留一个明确主路径；预览、下载、创建、保存等全局操作不能在多个固定区域重复出现。
- 局部异常处理、字段编辑、行操作和筛选动作不得塞进全局 Header。
- Header 高度变化必须参与锚点偏移、焦点滚动和 `scroll-margin-top` 计算；不能只依赖静态 CSS `sticky`。

## 4. Section / Subsection

- Section 表达稳定业务层级；Subsection 表达该业务组内的自然分组，不用于制造企业感。
- Object Page 必须有可定位的 Section、可见标题和当前章节反馈；长页面使用锚点或等价导航。
- Section 内的字段顺序以用户阅读和输出逻辑为准，不按底层字段 ID 或文件顺序排列。
- 不适用字段不渲染；低频来源、候选、历史和证据按需展开。
- 章节定位、Hash、返回、刷新和编辑保存后必须保持当前上下文。

## 5. 操作层级

| 层级 | 位置 | 示例 | 规则 |
|---|---|---|---|
| 页面级 | Header 或稳定的压缩 Header | 预览、下载、创建 | 一个页面级主路径；不与固定底栏重复 |
| Section 级 | Section Header | 编辑本组（仅在确有整组行为时） | 不用来替代字段级动作 |
| 对象/行级 | 字段行、列表行、卡片 | 编辑、处理问题、打开 | 靠近对象，保持上下文 |
| 溢出级 | 更多菜单 | 低频或次要动作 | 不隐藏唯一恢复路径和主要动作 |

## 6. Floorplan 规范

### Worklist

回答“现在先处理什么”。首屏包含任务身份、紧凑状态摘要、筛选/排序和第一条可操作任务。列表行必须给出下一步动作、阻塞原因和返回路径。空态提供下一步，不虚构 KPI；错误态说明恢复动作；批量动作不抢占单项任务。

### List Report

回答“如何找到一批对象”。页面由标题/主要动作、Filter Bar、结果计数、结果表或响应式卡片、行级操作组成。筛选状态可读、可清除；窄屏不得依赖横向滚动才能完成主要查找和操作；空结果与系统错误分开表达。

### Object Page

回答“这个对象整体是什么样”。使用 Dynamic Page Header、稳定 Section/Subsection、锚点/当前章节、安静字段和局部编辑。案件总览的申请人章节是第一个 Responsive Form 试点，不得复制成第二套案件数据或编辑系统。

### Responsive Form

回答“如何创建或编辑一组资料”。字段按业务组排列，简单字段靠近操作，复杂地址/备注/组合字段可跨列。有效内容宽度足够时可三列，常规桌面二列，窄屏一列；列数由可读性和字段复杂度决定，不为填满屏幕强行三列。保存、取消、错误和返回必须保持焦点与上下文。

- 正常字段不使用完整卡片边框；以网格、留白和轻分隔建立扫描秩序。缺失、冲突、格式错误和其他待处理字段可以保留明确的强调背景或边界。
- 当前正在编辑的字段必须有独立选中状态，且该状态不能只依赖颜色；保存或取消后回到触发字段。
- 编辑器按有效宽度重排：宽屏使用右侧局部面板；768–1199px 使用覆盖式侧边抽屉或当前字段下方展开；390px 优先使用底部或全屏编辑器。编辑器不得作为整个章节末尾的第二套编辑系统。

### Wizard

回答“如何完成有顺序的决策流程”。每一步有明确目标、完成条件、返回/前进语义、错误恢复和可回看的当前步骤。资料导入的上传、识别、归属、新建/追加/合并属于 Wizard；不能把 Wizard 变成长期对象编辑页。

### Preview & Confirmation

回答“最终将输出什么，用户确认什么”。预览必须来自当前案件事实和所选模板；阻塞原因可定位到业务问题；确认使用业务语言并绑定数据版本；数据变化后确认失效。预览页不重新承载全部案件整理工作。

### Relationship Explorer

只用于关系树等确实需要展示对象关系的辅助页面。关系可读、节点可键盘访问、返回路径明确；不得成为案件、主体、物件的第二套详情权威。

### Auth Shell / System State

认证、加载、错误和 Not Found 使用统一 Shell、语言、焦点、恢复和返回规则，但不冒充业务 Floorplan。系统状态要区分加载、空数据、权限拒绝、业务错误和不存在资源。

## 7. 响应式

- 目标视口至少覆盖桌面、平板和手机；阶段 A 目标图使用同一内容场景比较结构差异。
- 桌面优先利用有效宽度；平板重排字段组、操作和导航；手机优先保证查看、修改、返回和主要输出任务完成。
- Responsive Form 使用三/二/一列作为候选结构，不把固定像素列数写成业务事实；最终断点由目标图和浏览器证据确认。
- 日文、中文、韩文长标签允许换行；按钮、锚点、字段值、错误说明不能靠截断保持布局。
- 中日韩并排长文本样本只作为 QA 附图，用于验证换行和密度，不进入生产组件或正式业务数据展示。
- 不依赖横向滚动完成主任务；表格无法重排时必须提供等价的响应式行/卡片信息。

## 8. 状态语言

- Loading：说明正在加载什么，保留页面身份，避免内容跳动；不把加载当作空态。
- Empty：说明没有数据或没有匹配结果，提供下一步；不显示虚构的成功指标。
- Error：说明发生了什么、影响范围和可恢复动作；网络/权限/业务校验不能混成一个错误。
- Permission denied：说明没有权限并提供返回路径，不泄露对象存在性或跨租户数据。
- Normal：正常数据安静展示，不给每行重复绿色成功标签。
- Issue：缺失、冲突、格式错误、逻辑矛盾、覆盖风险、归属不明或系统无法可靠决定时才强调，并给出局部处理入口。

## 9. 无障碍

- 使用真实的 heading、landmark、button、link、form label 和表单错误关联；不要用 `div` 模拟交互控件。
- 所有主要操作可通过键盘到达；锚点具备正确的链接语义，当前章节使用可感知状态；打开编辑器后焦点进入正确字段，保存/取消/关闭后回到触发位置。
- 焦点轮廓不能只靠颜色；异常不能只靠颜色；控件触控目标至少满足现有 UI Foundation 的尺寸契约。
- 动态 Header、锚点、抽屉、弹窗和错误反馈变化必须对键盘和辅助技术可感知；不能让焦点落入不可见区域。
- 200% 放大、窄屏和中日韩长文本不得丢失主要操作、字段含义或错误原因。

## 10. 组件与 Token 边界

- Layout 组合组件负责结构、插槽、操作层级、响应式和焦点；领域组件负责案件、模板、主体和输出业务。
- Layout 组件必须复用 `src/components/ui-foundation/` 和 `src/app/globals.css` 的现有基础，不创建第二套颜色、间距、圆角、焦点或字体来源。
- 页面不能在本地复制一套 `DynamicPageHeader`、`ResponsiveFormLayout` 或状态组件；若确实有领域差异，使用明确的变体和证据说明。
- 公共组件只有在目标图批准后才能实现；阶段 A 文档和目标图不产生生产运行代码。

## 11. 目标图门禁

目标图不是生产页面，也不是静态截图替代品。批准前必须能回答：

- 同一 Shell 如何承载不同 Floorplan；
- 页面级和局部操作如何区分；
- Dynamic Header 压缩后如何保留身份和主要操作；
- 申请人 Responsive Form 在桌面/平板/手机如何重排；
- 正常、空、错误、加载和权限状态如何表达；
- 中日韩长文本、键盘焦点和返回路径是否仍可理解。

目标图批准后，正式实现仍必须通过浏览器、键盘、响应式、状态和业务回归验收。
