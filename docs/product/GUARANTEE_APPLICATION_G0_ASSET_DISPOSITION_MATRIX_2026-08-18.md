## 2. 处置原则

1. **不因权利未证而直接删除**：删除可能破坏历史输出、指纹校验、安装快照和回滚。
2. **不因代码已有 `verified` 而继续公开**：技术校准和法律/来源权利是两个独立状态。
3. **不把隐藏误写成退役**：隐藏表示暂时停止新用户访问；退役需要来源、历史输出和引用审计完成。
4. **不允许入口绕过门禁**：旧 route、直接 URL 和下载 API 都必须最终受兼容配置、权利状态、版本匹配和权限约束；公共撤下不自动等于租户私有业务失效。
5. **不在 G0 实施**：本矩阵只给出保留、改名、降级、隐藏、迁移、删除建议，不修改页面、API、数据库或资产。

## 3. 发布门分类

- **G1 技术建设门**：通用兼容配置对象、租户私有原件、填写层、版本链、四态匹配和输出快照可以进入 G1 设计与实现。
- **具体表单商业上架门**：五套现有平台蒙板必须等待上线前法律确认；证据不足时不向新客户正式上架原始表格/完整图片，但允许 G1 测试和现有生产行为。
- **上线前法律门**：最终保留期限、不可恢复删除、来源方撤下和具体内部使用边界必须在生产发布前取得法律确认。
