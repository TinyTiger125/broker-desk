# 首页验收标准 2026-06-27

## 目标

本文档定义测试上线前首页最后一轮修订的验收标准。

首页不能是泛泛的统计看板。它的任务是帮助经纪人快速回答四个问题：

1. 现在最需要我处理什么？
2. 哪个案件、客户、物件或资料卡住了进度？
3. 它和哪些资料有关？
4. 我下一步应该点哪里？

## 发布准入

首页只有在所有 P0 条目通过，并且 P1 条目没有明显视觉或流程倒退时，才算通过本轮修订。

- P0：本轮首页修订的上线阻断项。
- P1：两天测试上线前应尽量完成的体验项。
- P2：测试上线后可以继续优化，除非本轮顺手即可完成。

## P0 验收项

### 1. 首屏清晰度

- 桌面首屏必须有一个明确的当前重点工作项。
- 重点工作项必须显示状态、可读的原因，以及一个主操作。
- 同一个视觉区域内不能出现多个同等强度的主按钮。
- 搜索可以保留，但不能抢过主操作的注意力。
- 用户不需要读说明文字，也能知道首页是用来继续处理资料和案件的。

通过测试：看 5 秒后，用户能说出当前要处理哪一项，以及下一步应该点哪个按钮。

### 2. 资料关系图必须有意义

- 关系区必须以一个选中或推荐案件为中心。
- 必须展示主体、物件、关联资料、输出路径之间的连接，而不是只展示数量。
- 至少一个关系节点必须说明当前卡点或下一步动作。
- 关系标签使用业务语言：案件、客户/关系人、物件、已关联资料、输出文件。
- 不得出现字段数、数据库字段名、抽取表字段数等内部指标。

通过测试：用户能从关系图回答“这个案件挂了什么资料”和“现在为什么还不能顺畅往下走”。

### 3. 工作队列优先级

- 待处理项目必须排在已完成项目之前。
- 首页推荐项应该和列表中最高优先级的待处理对象一致。
- 状态文案必须有行动含义，例如：`待整理`、`待归属`、`需要确认`、`可输出`。
- 如果没有待处理项，也必须给出明确下一步：新建案件、导入资料或进入输出中心。

通过测试：首页给人的感觉是工作队列，而不是统计页。

### 4. 筛选交互反馈

- 分类筛选必须有明显的当前选中状态。
- 点击分类后，用户必须能看到列表已切换，或页面已带用户到列表上下文。
- 列表标题必须重复当前筛选类型和数量。
- 清除筛选必须明确，不应意外清掉用户仍然需要的搜索上下文。

通过测试：点击分类后，用户马上知道页面发生了什么变化。

### 5. 中文本地化自然

- 产品 UI 和流程动作必须翻译成当前语言。
- 人名、地址、楼名、公司名等原始专名不要硬翻译。
- 中文 UI 中保留日本资料原文是允许的，只要它属于数据本身。
- 中文模式中不应出现误留的日文 UI 词，除非它是专名或原始文件名。

通过测试：中国用户操作日本房产业务资料时，界面可读且不别扭。

## P1 验收项

### 6. 分类摘要应像筛选器

- 四个对象分类应被理解为筛选入口，而不是主要内容。
- 分类摘要应足够轻，不与关系图和工作队列争抢视觉中心。
- 数量只保留用户能理解的总数和待处理数，不显示无法解释的内部数字。

通过测试：用户把分类看成导航，不把它当成首页的核心内容。

### 7. 选中项面板应帮助行动

- 右侧选中项面板应帮助用户行动，而不是重复列表信息。
- 面板应包含状态、原因、关键关系、更新时间和主操作。
- 次要事实应减少、隐藏或放到主操作之后。
- 如果选中的是导入资料，操作应指向归属或整理。
- 如果选中的是案件，操作应指向继续整理或输出准备。

通过测试：面板能回答“这项为什么重要”和“我现在能做什么”。

### 8. 视觉层级和密度

- 首屏最多保留三个主要决策区域：
  1. 推荐工作项；
  2. 关系/卡点上下文；
  3. 对象列表或轻量筛选入口。
- 对行动没有帮助的重复边框、大卡片、大数字块应减少。
- 桌面和移动端文字不得裁切、遮挡或挤出容器。
- 大字号只用于页面身份或当前重点任务，不用于小面板。

通过测试：用户的视线先落在下一步任务，而不是统计数字或次要面板上。

### 9. 移动端可用性

- 390px 宽度下，用户不需要横向滚动即可看到当前工作项和主操作。
- 次要导航、账号、语言、角色控制不能占据首屏主要注意力。
- 主按钮必须可点击，且不能被悬浮角色标识遮挡。
- 关系图可以纵向堆叠，但标签和状态必须可读。

通过测试：移动端可以不是最终完美版，但不能像被压窄的桌面页。

### 10. 基础可访问性

- 卡片式链接必须有有意义的可访问名称。
- 纯装饰 Material Symbols 不应被读屏误读成操作文字。
- 链接、筛选、按钮、搜索框必须有可见焦点态。
- 状态不能只靠颜色表达，必须有文字。
- 键盘访问顺序应能自然经过搜索、筛选、列表、选中项操作和主导航。

通过测试：只用键盘也能走通首页主路径。

## P2 验收项

### 11. 空状态和全完成状态

- 没有待处理项时，首页应从“工作队列”切换为“开始新工作”模式。
- 空状态应推荐一个动作，而不是展示空面板。
- 推荐动作可以是新建案件、导入资料或进入输出中心，取决于已有数据。

### 12. 信任和证据

- 如果关系或卡点来自导入资料或 AI 建议，用户应能在下一屏看到来源或证据。
- 首页不能暗示未经确认的抽取数据已经成为已确认事实。

### 13. 性能感知

- 首页不应明显闪过未翻译或未本地化状态。
- 如果后续加入加载状态，应保持布局高度，避免页面跳动。

## 复核清单

本轮首页修订完成前，必须截图并复核：

- 桌面默认状态。
- 桌面四类筛选状态。
- 桌面选中案件行状态。
- 桌面选中导入资料行状态。
- 390px 移动首屏。
- 移动端关系区域。
- 中文语言下含日本专名的数据。
- 日文语言冒烟检查。

必须通过的工程检查：

- `npm run lint -- --quiet`
- `npx tsc --noEmit --pretty false`
- `npm run test:ja-terms`
- `npm run test:case-field-catalog`

## 本轮不做

- 不重做整个应用壳层。
- 不把首页改成 CRM 数据分析看板。
- 不展示原始抽取字段数这类内部指标。
- 不把日本人名、地址、楼名、公司名硬翻译成中文。
- 不引入案件、主体、物件、资料、输出之外的新大概念。
