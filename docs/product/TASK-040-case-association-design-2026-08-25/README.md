# TASK-040 案件资料关联器：设计交付包

状态：**Product Contract Approved / Documentation Cleanup Required / Implementation Not Authorized**（2026-08-25）

本交付包把现有 Broker Desk 的案件创建、整理中心和案件详情作为基线，设计两条 V1 关联流程：

1. 创建案件时选择已有资料，或快速创建人物/物件并加入案件草稿；最终创建案件时一次性保存案件和全部关联；
2. 整理已有案件时管理人物角色、人物关联和唯一主要物件。

本包不修改 `src/`、数据库、migration、权限合同或部署配置；未创建产品原型代码。

## 本轮修订结论

以下合同已写入六份设计文档：

1. 新建案件页的已有资料选择和快速创建均进入案件草稿；案件创建时案件和全部关联一次性保存。
2. 新建案件页快速创建反馈固定为“主资料已创建，并已加入本次案件草稿；创建案件后正式关联。”；取消案件时主资料保留。
3. 已有案件详情继续使用“创建主资料 → 写入案件关联”的两阶段反馈。
4. 候选只要求当前用户拥有可写能力；本人拥有且公司可见的资料仍可关联，只有他人仅有公司成员可见／只读权限的资料不可成为候选。
5. 人物角色固定为“主要申请人、承租人、同住人、连带保证人、紧急联系人、出租人／业主、其他关联人”；同一人物允许多个角色。
6. 一个案件最多一个主要申请人；案件可以暂缺主要申请人或主要物件；保证公司申请书仅在二者齐备且当前用户有权使用时生成。
7. 公司负责人、表格管理员不能绕过资料权限；本人是当前负责人时按正常可写规则操作。
8. 用户界面不显示内部权限术语，统一使用“可关联”“仅自己可见”“公司成员可见／只读”等产品语言。
9. 已关联人物进入“编辑角色”；删除最后一个角色必须转为“解除关联”确认，不重复创建关系。
10. 主要物件可更换和解除；解除后案件可暂时没有主要物件，相关输出提示缺失条件。
11. 快速创建复用现有人物、物件创建合同，不定义第二套字段或校验规则。
12. 桌面抽屉、窄屏全屏层补齐焦点锁定、关闭恢复、键盘操作、错误关联保留和固定底栏遮挡检查。

## 已关闭的产品裁决

- V1 案件草稿只在当前页面会话内保留，不跨刷新、离开页面或重新进入页面持久化。
- 日文、韩文最终文案进入实现验收；本设计只规定复用现有创建合同，不复制字段规则。
- 取消案件后不提供主资料直达链接；取消和返回提示必须明确说明快速创建的独立主资料仍然保留。
