# 用户流程图

图中“可关联候选”指当前 session 下当前用户拥有可写能力的人物/物件；资料是“仅自己可见”还是“公司成员可见／只读”不改变本人候选资格。其他成员仅有公司成员可见／只读的资料在候选源头被过滤，不进入后续步骤。图中的“草稿”表示案件尚未创建前的页面内待保存状态，不表示关系已经落库。

## 1. 创建案件：选择已有资料

```mermaid
flowchart TD
  A[进入新建案件] --> B[填写案件类型与案件名]
  B --> C{关联资料}
  C -->|选择已有物件| P[打开选择已有物件抽屉]
  C -->|选择已有人物| Y[打开选择已有人物抽屉]
  P --> P1[搜索/筛选可写物件]
  P1 --> P2{结果}
  P2 -->|无结果| P3[显示无可建立关联的资料]
  P2 -->|已在本次草稿| P4[标记当前主要物件并禁用重复加入]
  P2 -->|可选| P5[选择物件]
  P5 --> P6{案件草稿已有主要物件?}
  P6 -->|否| P7[加入案件草稿并显示主要物件摘要]
  P6 -->|是| P8[进入更换草稿主要物件确认]
  Y --> Y1[搜索/筛选可写人物]
  Y1 --> Y2{结果}
  Y2 -->|无结果| Y3[显示无可建立关联的资料]
  Y2 -->|已在本次草稿| Y4[显示已在本次草稿与已有角色]
  Y2 -->|可选| Y5[选择人物]
  Y5 --> Y6[选择一个或多个案件角色]
  Y6 --> Y7[确认加入本次案件草稿]
  P7 --> D[检查关联摘要]
  P8 --> D
  Y4 --> D
  Y7 --> D
  D --> S{创建案件}
  S -->|校验失败| E1[保留案件草稿与已选资料，显示字段级提示]
  S -->|权限/关联冲突| E2[案件与全部关联均不保存，显示统一失败提示]
  S -->|成功| F[案件与全部关联一次性保存]
  F --> G[显示“案件已创建；本次案件草稿已提交”反馈]
```

## 2. 创建案件：快速创建并加入案件草稿

```mermaid
flowchart TD
  A[新建案件关联区] --> B{快速创建}
  B -->|快速创建人物| P1[打开现有人物创建合同]
  B -->|快速创建物件| R1[打开现有物件创建合同]
  P1 --> P2[填写最小必需字段]
  R1 --> R2[填写最小必需字段]
  P2 --> V1{字段校验}
  R2 --> V2{字段校验}
  V1 -->|失败| E[留在抽屉，定位错误，不丢案件草稿]
  V2 -->|失败| E
  V1 -->|通过| P3[创建人物主资料]
  V2 -->|通过| R3[创建物件主资料]
  P3 --> P4[将人物与角色加入案件草稿]
  R3 --> R4[将物件加入案件草稿的主要物件位]
  P4 -->|成功| P5[显示“主资料已创建，并已加入本次案件草稿；创建案件后正式关联。”]
  R4 -->|成功| R5[显示“主资料已创建，并已加入本次案件草稿；创建案件后正式关联。”]
  P3 -->|失败| P6[主资料未创建，保留案件草稿并显示错误]
  R3 -->|失败| R6[主资料未创建，保留案件草稿并显示错误]
  P5 --> C[用户点击创建案件]
  R5 --> C
  C -->|失败| C1[案件与全部关联均不保存；保留草稿并可重试]
  C -->|成功| C2[案件与全部关联一次性保存]
```

新建案件页的快速创建必须区分“主资料创建”和“案件正式关联”两个时间点：

1. 主资料创建成功，并加入本次案件草稿；
2. 用户创建案件成功，案件与全部关联一次性保存。

第一阶段反馈固定为“主资料已创建，并已加入本次案件草稿；创建案件后正式关联。”。用户取消案件时，独立主资料保留。新建案件创建失败时，不产生部分案件关联，保留页面草稿并允许重试；主资料不自动删除。

已有案件详情的快速创建仍是两阶段：先创建主资料，再写入案件关联。关联失败时显示“主资料已创建，但案件关联未保存”，保留主资料并提供重试，不自动删除。

## 3. 整理已有案件：人物关联

```mermaid
flowchart TD
  A[案件详情 / 关联资料] --> B[人物关联列表]
  B --> C{当前用户是案件当前负责人且有可写能力?}
  C -->|否| D[只读展示：角色、关联时间、主资料状态]
  C -->|是| E[增加人物]
  E --> F[选择已有可写人物抽屉]
  F --> G{已关联?}
  G -->|是| H[显示已有角色，禁止重复添加]
  G -->|否| I[选择一个或多个角色]
  I --> J[确认加入人物并保存角色]
  J -->|失败| K[保留抽屉选择，显示保存失败]
  J -->|成功| L[列表新增人物，显示已关联反馈]
  B --> M[人物行更多]
  M --> N[编辑角色或解除关联]
  N --> N1{是否删除最后一个角色?}
  N1 -->|否| N2[保存剩余角色]
  N1 -->|是| O[确认：只移除本案件关系，不删除主资料]
  O -->|取消| B
  O -->|确认| P[解除成功，刷新关联列表]
```

## 4. 整理已有案件：主要物件

```mermaid
flowchart TD
  A[案件详情 / 关联资料] --> B{已有主要物件?}
  B -->|否| C[设置主要物件]
  B -->|是| D[显示主要物件摘要]
  C --> E[选择已有可写物件抽屉]
  D --> D1[可选择更换或解除主要物件]
  D1 -->|解除| D2[确认解除；案件暂缺主要物件]
  D1 -->|更换| E
  E --> G{选中同一物件?}
  G -->|是| H[显示当前主要物件，禁用确认]
  G -->|否| I[确认更换主要物件]
  I -->|取消| D
  I -->|确认| J[保存唯一主要物件关系]
  J -->|失败| K[原主要物件保持不变，显示失败]
  J -->|成功| L[显示新主要物件 + 记录变更]
```

## 5. 跨流程状态规则

- 任一 drawer/全屏层打开后焦点锁定在层内；Tab/Shift+Tab 不逃逸，Enter 执行当前控件，Esc 等价于取消，不等价于保存；关闭后焦点回到打开它的按钮。
- 保存期间按钮进入 loading，避免重复提交；失败不清空已选内容。
- 详情刷新后以服务端结果为准；客户端暂存只用于恢复表单，不用于授权。
- 其他成员仅有“公司成员可见／只读”的资料可在已有合法关联详情中按只读状态显示，但不进入“选择已有”候选；这不是“搜索不到”，而是“当前动作不可建立关系”。
- 新建案件页底栏固定动作不能遮挡草稿摘要、错误或抽屉确认；窄屏全屏层的滚动内容必须预留底栏高度，背景底栏在层打开时不可误触。
