# 线框与交互状态

本文件是当前唯一有效的线框。它只表达结构、层级、状态和文案，不是实现稿；按钮和状态标记对应现有 UI Foundation 组件。真实 `/cases/new` 截图和键盘回归在首次 Staging 实现验收时补齐。

### 3.1 新建案件人物抽屉状态


## 5. 快速创建：复用现有人物／物件创建表单

快速创建不另画姓名、电话或其他虚构的最小字段。它打开现有人物或物件创建表单，复用该表单的字段、必填项、校验、权限和保存合同；设计包只规定返回案件草稿后的状态。

```text
┌─ 现有人物创建表单 ───────────────────────────┐
│                                             │
│        现有人物创建表单的完整字段与校验      │
│        （由既有创建合同提供）                 │
│                                             │
│ [取消]                         [创建人物]   │
└─────────────────────────────────────────────┘

创建成功后返回新建案件页：
主资料已创建，并已加入本次案件草稿；创建案件后正式关联。
```

物件快速创建使用同一结构并调用现有物件创建表单。用户取消新建案件时，独立主资料保留；本轮不提供主资料直达链接。

## 9. 桌面抽屉与窄屏全屏层

### 桌面抽屉

- 打开后焦点进入标题或搜索框；Tab/Shift+Tab 只在抽屉内循环。
- 结果行、角色选择、取消、确认和关闭按钮均可用键盘到达；Enter 执行当前控件；Esc 取消并关闭。
- 抽屉内容区独立滚动，固定操作栏位于抽屉内部；最后一行、角色错误和保存错误不得被底栏遮挡。
- 抽屉打开时，页面底部“创建案件”不可误触；用户必须先关闭抽屉。
- 关闭、取消和失败均恢复原页面滚动位置及触发按钮焦点；失败不清空草稿。

### 窄屏全屏层（≤768px）

- 全屏层打开后锁定背景焦点和背景滚动；Tab/Shift+Tab 不进入背景页面。
- 结构固定为标题区、可滚动内容区、底部固定操作栏；内容区预留底栏高度，最后一项和错误不被遮挡。
- 全屏层内不嵌套第二个 modal；更换物件和解除确认在同一层内完成。
- 页面只保留一个主提交动作：底部“创建案件”。顶部不出现“保存”或其他重复主提交按钮。
- 关闭、取消和失败均恢复原页面滚动位置及触发按钮焦点。

## 10. 文案边界

- 新建案件页：使用“案件草稿”“已加入本次案件草稿”“已在本次草稿”。
- 已有案件详情：使用“已关联”“编辑角色”“解除关联”。
- 不显示内部权限或可见性术语；用户文案使用“可关联”“仅自己可见”“公司成员可见／只读”。
- 新建案件页只使用草稿状态；已有案件详情才使用正式关系状态。
