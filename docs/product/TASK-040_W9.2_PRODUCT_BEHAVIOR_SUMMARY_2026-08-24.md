# TASK-040 W9.2：一页产品行为摘要

**状态：** TASK-040 `In Progress`；W9.2 只读盘点与技术设计已通过，当前仅实施首两个安全硬门，统一可见性解析器尚未开始。
**验证环境：** 仅非生产；Production 禁止部署、连接和 migration。

## 用户能看到什么

### 默认行为

- 案件、人物、物件新建时默认“仅自己可见”。
- 每名成员在每个经营主体中，分别为案件、人物、物件设置自己的默认值；不同公司、不同对象类型互不影响。
- 默认值只影响之后新建/导入资料，不追溯改变已有资料。

### 两种可见范围

1. **仅自己可见**：只有当前资料负责人能读取和编辑。
2. **公司成员只读可见**：同一经营主体的 active 成员可以读取；只有资料负责人可以编辑、改范围或改变负责人。

没有第三种定向分享、共同编辑、部门权限或公司负责人通览模式。

### 负责人和创建者

- 新建/导入时，创建者和当前负责人初始可相同，但两者不是同一个字段。
- 创建者是不可变历史事实；普通编辑、改范围和未来负责人变更都不能改写。
- 当前负责人未来可以通过独立、受控接管专题变化；W9.2 不提供接管入口。
- 无法可靠识别旧数据负责人时，资料保持“负责人待确认”，普通成员看不到，不自动归公司负责人、不自动公开、不自动删除。

## 用户不能看到什么

- 非负责人不能看到 private 资料是否存在，不能通过列表数量、分页、搜索建议、空状态、导出、错误、关系线索或附件名称推断。
- 公司负责人和表格管理员没有员工私有案件、人物、物件的内容绕过权。
- suspended、removed、缺失身份、失效工作区和跨经营主体上下文不能继续读取资料。
- company_read 成员不能编辑资料、附件、关联关系、范围或负责人。

## 页面和接口的一致行为

- 列表、详情、搜索、建议、分页数量和导出只计算当前用户有权看到的资料。
- 直接访问无权 URL 统一显示“未找到或无权访问”，不区分“资料不存在”和“资料存在但无权”。
- 每次请求都重新确认用户、当前公司和 active membership；切换公司、刷新、返回和预取不能把上一身份/上一公司的内容带入。
- 客户端隐藏按钮不是安全边界；Server Action、API 和数据库 RLS 都必须拒绝越权写入。

## 当前阶段不包含

- 定向分享、共同编辑、部门/团队权限。
- 资料接管、接管审计、停付费长期留存/删除。
- 关系图、附件权限、PDF 来源权限交集和历史下载改造。
- Production 数据迁移、Production 发布和商业容量/法律规则。

## 验收前提

W9.2 进入有限实现前，必须先通过创建者不可变门：普通更新、负责人变化、范围变化、客户端伪造字段、合并/拆分和运行角色 SQL 都不能改变 `created_by_user_id`。随后分别用案件、人物、物件验证 private、company_read、pending、active/suspended/removed、跨经营主体、搜索/count/export 和多工作区缓存隔离。

## 本轮最终合同

- 运行期授权只看当前 owner、scope、resolution、当前 tenant 和 active membership；旧 `user_id/owner_user_id` 不能作为授权 fallback。
- 普通请求提交 creator、current owner、tenant 或 actor 字段必须被拒绝并记录安全事件。
- 无独立可见范围的子资料继承父对象；引用其他对象时重新鉴权。
- `company_read` 成员可以读取、搜索、导出，但页面明确显示只读，所有写接口拒绝。
- 首先只关闭搜索 API 认证/tenant/default-user 硬门和 creator immutable 硬门；两项通过后才逐类修改案件、人物、物件页面。
- 关系图、附件、PDF 来源交集、历史下载、接管、定向分享、共同编辑和 Production 仍排除。
