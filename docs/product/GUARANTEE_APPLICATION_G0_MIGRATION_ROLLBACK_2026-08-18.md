# 保证公司申请书专题：迁移与回滚清单

- 制定日期：2026-08-18
- 状态：G0 原则合同；不执行迁移
- 目标：在进入 G1 前确定旧数据、旧语义、旧链接和版本历史的可逆处理

## 1. 迁移清单

| 旧结构 | 迁移原则 | 不得做的事 | 回滚边界 |
| --- | --- | --- | --- |
| `guarantee_application_drafts` 的个人 `user_id` 维度 | 保留原操作者；新产品所有权归租户；先建立租户归属映射，再决定草稿合并/保留 | 不把个人草稿静默合并成公司已发布配置；不删除离职操作者历史 | 旧草稿表和快照只读保留；迁移失败不影响原草稿读取 |
| “官方模板/官方原件”语义 | 新目录改称兼容配置/租户空白原件；历史记录保留原显示值但标记历史 | 不把旧字段值重新解释为已授权或官方合作 | 新旧标签可通过兼容映射恢复；旧审计事件不可改写 |
| `purchased_seat_count` 与席位限制 | 目标产品不以该字段限制公司成员数量；旧字段和旧计费状态保留为兼容数据 | 不在 G0 删除字段、直接解除生产限制或改变计费事实；成员页面不展示席位占用目标语义 | 保留旧字段和旧限制开关；订阅迁移/回滚验证完成前回到旧成员状态；验证后才切换目标状态 |
| 八角色与模板动作 | 保留角色 ID，增加三维能力映射；模板管理采用正交预设 | 不把 `tenant_admin` 自动改名为模板管理员；不删除旧角色 | 新预设可按租户关闭；旧角色权限和审计继续可读 |
| `tenant_guarantee_template_installs` | 保留平台来源版本、指纹和租户冻结快照；未来补租户覆盖/自建版本链 | 不用平台新版本静默覆盖旧安装；不把安装当作权利证明 | 旧安装可继续读取；新版本发布失败不改变旧安装 |
| 历史输出 `generated_outputs` | 保留原输入、布局、操作者、时间和文件记录；增加原件/字段目录/填写层关联只对新输出生效 | 不重算或覆盖历史输出；不因公共目录撤下自动删除或停止租户历史业务 | 历史输出继续按合法保留规则追溯；只有法律要求、安全风险或匹配失效才阻断相关新输出 |
| `public/guarantee-templates/*` 与静态源资产 | 先隐藏公共展示、保存指纹和引用清单；权利补证后决定迁移至租户原件或退役 | 不直接删除导致预览/快照/回滚断链 | 原路径和资产指纹保留到引用审计完成；可恢复旧内部预览 |
| 旧 `/templates`、`/platform/templates`、预览/下载链接 | 保留兼容路由壳；新入口通过权利、版本、匹配和权限门禁；旧直接 URL 不能绕过 | 退役不按固定日期；必须先有替代入口验证、无活动调用、安全只读/恢复路径和回滚演练 | 旧路由可回到只读历史/安全入口；新门禁失败不损坏旧数据 |

## 2. 迁移顺序

```text
证据与权利登记
  → 资产/入口引用清单
  → 租户/个人对象归属映射
  → 权限兼容映射
  → 新版本链双读验证
  → 新输出快照验证
  → 分租户启用
  → 旧入口降级/退役
```

任何一步失败，都应停止后续切换，保留旧读路径和旧历史。不得先删除旧资产再尝试迁移。

## 3. G1 验证项与上线前门

- **G1 技术验证项**：个人草稿到租户对象映射、权限预设、安装关系双读、历史输出快照关联、旧路由引用扫描、订阅迁移和回滚演练。
- **上线前法律门**：原件/配置保留期限、不可恢复删除、来源方撤下、租户权利声明和平台协助授权。
- **具体表单商业上架门**：五套现有平台蒙板在法律结论前不正式上架给新客户；可继续作为 G1 测试样本并维持现有生产行为；通用平台蒙板和公司自建蒙板能力不被该缺口阻断。
- **旧路由退役门**：替代入口通过流程验证、没有活动调用依赖、历史链接有安全只读/恢复路径、回滚演练通过。

## 4. 回滚触发条件

- 跨租户读取、成员停用后仍可访问或平台人员意外读取客户案件；
- 历史输出无法读取、版本快照无法解释或新输出引用错误版本；
- 原件指纹变化未触发重新校准；
- 公共配置权利证据撤回或来源方要求停止公共传播；租户私有原件只有在有效法律要求、安全风险或匹配失效时才触发相关新输出阻断；
- 旧安装/草稿无法映射到租户且会造成数据丢失；
- 新权限预设使合法成员无法使用已发布配置或让普通成员进入编辑器。

## 5. 回滚动作

1. 停止新配置发布和新输出生成；
2. 将活动版本指针恢复到上一已验证版本；
3. 保留并锁定受影响的原件、填写层和输出快照；
4. 恢复旧只读入口或安全 System State；
5. 保留失败审计、操作者和版本差异；
6. 只有在产品/技术/法律共同确认后，才继续迁移或执行资产退役。

## 6. G0 不做的迁移动作

- 不执行数据库迁移、删除或回填；
- 不修改权限/认证/租户实现；
- 不关闭 TASK-020 或恢复退役打印路由；
- 不把外部产品的版本比较、电子签名或 API 直接复制进当前实现；
- 不因为“兼容”而给无权利证据的表单补造来源或授权。
