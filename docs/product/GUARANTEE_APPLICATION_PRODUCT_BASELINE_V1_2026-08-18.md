# 保证公司申请书：第一版产品基线

- 制定日期：2026-08-18
- 状态：G0 产品验收通过；G1 依赖图和切片规划已授权，尚未授权实现
- 权威级别：本页是本专题面向产品和用户的最高产品依据。G0 研究、对象、权限、迁移和外部模式附件若与本页冲突，以本页为准。

## 1. 产品替谁解决什么问题

Broker Desk 面向同一经营主体内的房地产从业成员，帮助他们把案件中已经整理好的事实，套用到不同保证公司或其他申请接收方要求的表格中，减少重复录入、漏填和格式错位。

当前第一版采用 PDF 兼容路线：客户提供自己合法取得的**客户空白表格**，Broker Desk 使用不含第三方原始 PDF 的**平台蒙板**或**公司自建蒙板**，生成**已生成文件**。PDF 是没有直接接口时的兼容手段，不是 Broker Desk 的长期产品终局；未来可以另行建设申请接收方的直接数据联携，本版不实现。

## 2. 普通成员如何生成申请书

普通成员从案件开始：

```text
案件
  → 选择保证公司／表格
  → 系统匹配蒙板与客户空白表格
  → 补齐少量申请书专属信息
  → 预览
  → 生成文件
```

匹配不明确、表格不兼容或需要重新校准时，系统停止生成并说明下一步。普通成员不能移动字段坐标或进入抠格子工具；错位只能交给公司表格管理员重新校准。普通成员的日常入口不是蒙板编辑器。

## 3. 公司表格管理员如何制作蒙板

公司表格管理员上传本公司的**客户空白表格**，然后：

1. 使用可用的**平台蒙板**，或从零制作**公司自建蒙板**；
2. 人工抠格子，绑定 Broker Desk 案件字段、格式和校验；
3. 使用测试案件预览，检查溢出、复选框、日期和分页；
4. 测试通过后，发布给本经营主体内的成员使用；
5. 需要修正时发布新版本，不覆盖历史**已生成文件**。

平台蒙板和公司自建蒙板只保存坐标、字段关系、格式/校验和匹配元数据，不保存或分发保证公司的原始 PDF、高清背景或完整表格图片。

## 4. 平台如何提供高频蒙板

平台运营者可以选择高频通用表格，人工制作**平台蒙板**，使用受控测试案件验证。只有在来源、权利、质量和版本条件满足后，平台蒙板才可以面向新客户提供使用。

平台不向客户目录提供保证公司的原始 PDF 或完整表格图片。当前仓库中的五套配置统一称为“五套现有平台蒙板”：它们可以继续作为 G1 的真实测试样本，并支持现有匹配、校准、预览、输出链路和当前生产行为；在上线前法律确认完成前，不把它们正式上架给新客户，能否作为商业产品面向所有客户提供另列为上线前法律确认项，也不把它们判定为永久不能输出。

## 5. Broker Desk 保存什么、不保存什么

Broker Desk 保存：

- 案件权威事实和申请书补充字段；
- **平台蒙板**或**公司自建蒙板**的坐标、字段关系、格式、校验、匹配条件和版本；
- **客户空白表格**的租户内文件记录、指纹和版本元数据（文件由客户上传，不成为公共目录资产）；
- **已生成文件**及其案件版本、表格指纹、蒙板版本、字段目录版本、操作者和时间记录。

Broker Desk 不以产品资产形式保存或向客户分发第三方原始 PDF、完整表格图片或高清背景；不把普通成员的临时坐标调整作为第一版能力；不把五套现有平台蒙板重新称为保证公司官方产品。

## 6. 第一版不做什么

- 不做保证公司或 At Home、ITANDI、いえらぶ等申请接收方的 API 直连；
- 不做电子签名、文档协同审批或跨租户共享；
- 不做普通成员坐标调整或第二套临时编辑器；
- 不做 AI 自动画框作为发布或输出门槛；
- 不做模板市场、用户出售蒙板或多语言表单设计器；
- 不把 Broker Desk 自有报价单或其他业务表单夹带进本专题；
- 不恢复退役打印路由，不改变 TASK-020；
- 不把置信度、输出资格或伪完成度做成日常用户状态。

## 7. 哪些事项只阻断正式上线，哪些不阻断 G1

可以进入 G1 通用技术建设和测试的内容：客户上传空白 PDF、私有租户存储、平台蒙板/公司自建蒙板、匹配与四态判断、人工校准、测试预览、版本发布、已生成文件快照，以及五套现有平台蒙板作为真实测试样本和现有生产兼容资产。

只阻断面向新客户正式上架或生产发布的事项：第三方原始 PDF 或完整图片的展示/分发权证据、平台蒙板是否需要额外授权、最终文件保留和不可恢复删除规则、具体表单面向所有客户的商业上架资格，以及上线前的法律和质量门。这些事项不被产品经理自行推导；在结论形成前不扩大对现有生产行为的改变。

G0 已通过本页及纠偏摘要验收；当前仅授权 G1 依赖图和切片规划，不授权实现、生产行为变更或具体表单商业上架。
