# TASK-020：实施 C+ 案件总览

- 状态: Ready
- 优先级: P0
- 负责人: 技术项目经理 / 实现 Agent / 独立审查 Agent
- 依赖关系: TASK-018

## 任务名称

在现有案件工作台内实施 C+ 案件总览：以案件内容为主、异常按需处理、输出在下载动作中完成业务确认。

## 背景和用户结果

用户打开案件后首先看到完整案件，而不是 AI 读取过程或异常列表；用户可以通读、修改和定位问题，并在申请书下载前确认将用于生成申请书的当前案件信息。

## 已批准设计基线

- C+ = C 的案件阅读结构 + A 的顶部分类锚点 + 默认收起的待处理队列。
- 页面模式暂定为“快速补全 / 案件总览”；本任务只收敛案件总览，同时保持现有快速补全入口可用。
- 首屏顺序：案件身份 → 模式切换 → 紧凑输出阻塞摘要 → 分类锚点 → 案件字段。
- 正常字段安静展示；异常字段在对应行显示明确问题和“处理问题”。
- 正常字段只提供“编辑”；不提供未定义行为的“编辑本组”。
- 顶部只保留一次“申请书预览”；摘要区域只提供“查看问题”。
- 下载按钮保持可见。存在阻塞时显示具体阻塞原因；无阻塞时，下载动作触发一次案件级业务确认。
- 用户文案为：“请确认当前案件信息将用于生成申请书。案件信息修改后，需要重新确认。”内部仍可使用数据版本绑定确认状态。
- 正式表单原始日文标题由模板提供并保持不变；案件名称不得直接拼接成“住宅贷款申请”或“保证会社申请书案件”等未经确认的产品标题。

### 明确不照搬 SAP

- SAP 品牌视觉、颜色、图标、控件皮肤和企业 Shell。
- 复杂企业工具栏、与本产品无关的保存版本、相关应用和配置入口。
- 全局整页编辑模式。
- 与案件申请流程无关的表格、配置和管理能力。
- 为了制造“企业感”增加的额外层级。
- SAPUI5、SAP Fiori Elements 或其他 SAP 技术框架本身。

### 独立审查追加门禁

独立审查除本卡原验收标准外，必须逐项检查：动态头部是否合理压缩；锚点是否真实跟随滚动并高亮；编辑前后是否保持位置；页面提醒是否重复；长页面是否存在明显性能或定位问题；键盘焦点是否可恢复；实现是否错误引入 SAP 的复杂度。

## 本次范围

- 在现有 `/cases/[id]` 案件工作台中增加或调整案件总览视图，不建立第二套案件数据或独立编辑系统。
- 实现全宽连续阅读、顶部吸顶锚点、当前章节高亮、键盘可聚焦和编辑后滚动位置保持。
- 保持适用字段规则：展示当前案件适用字段，不机械展示底层全部字段。
- 保持候选数据与最终案件数据的底层分离，但不把底层分离强制映射为逐字段用户确认。
- 保留缺失、明确冲突、格式错误、逻辑矛盾、人工值覆盖风险、资料归属不明和系统无法可靠决定等异常处理能力。
- 异常队列默认收起；从摘要或下载阻塞原因可以展开并定位到对应字段。
- 正常字段按复杂度使用现有或适配后的轻量编辑方式；复杂字段和证据查看不在本卡内重新设计完整编辑系统。
- 保持预览可进入；最终下载阻止必填缺失、明确冲突、格式错误和模板渲染错误。
- 下载前案件级确认绑定当前案件数据版本；任何案件数据变化自动使确认失效。
- 使用 `docs/operations/PRODUCT_TERMINOLOGY_CANONICAL.md` 作为用户可见术语来源，按界面语言统一文案。

## 验收标准

1. 案件总览首屏同时出现案件身份、模式切换、紧凑阻塞摘要、分类锚点和第一组案件字段。
2. 待处理队列默认收起；摘要显示 `待处理（N）` 和 `展开`；展开后每个问题可定位到具体字段。
3. 正常字段不显示来源、置信度、确认状态或解释性状态标签；异常字段有文字和非颜色单一表达，并只提供“处理问题”。
4. 正常字段可以编辑；异常字段可以进入相应处理；不出现没有对应行为定义的“编辑本组”。
5. 页面只保留一个全局“申请书预览”入口；案件可以在有阻塞时进入预览。
6. 有阻塞时点击下载，显示具体阻塞原因和返回检查路径，不伪装成下载成功。
7. 无阻塞时点击下载，显示业务语言的案件级确认；确认成功后按当前案件信息生成下载，不显示“确认版本”等技术术语。
8. 修改案件数据、处理覆盖风险或新资料进入后，案件级确认自动失效，重新下载必须再次确认。
9. 顶部锚点吸顶、当前章节高亮、键盘焦点可见；编辑字段后滚动位置保持或有明确可理解的返回位置。
10. 中、日、韩界面文案分别来自当前术语规范；官方表单原始日文标题不被案件工作台文案覆盖。
11. 不回归资料确认/新建/追加/合并、案件工作台权限、数据持久化、模板安装、申请书预览和下载闭环。
12. 完成实现 Agent 和独立审查 Agent 的顺序审查；静态检查、浏览器行为、数据版本失效和差异范围证据齐全，工作区干净。

## 最小验证场景

- 打开健康案件：首屏先读到案件内容，不先处理异常。
- 展开待处理队列：点击一项后跳到对应字段并打开正确处理入口。
- 编辑一个正常简单字段和一个复杂字段：保存后位置可理解，确认状态失效。
- 在有缺失或冲突时预览并点击下载：预览允许，下载显示具体阻塞原因。
- 清除阻塞后点击下载：出现业务确认，确认后下载成功。
- 确认后修改任意字段或模拟新资料进入：下载再次需要确认。
- 使用键盘访问模式切换、锚点、异常处理、编辑、预览和下载。
- 使用三种界面语言检查术语来源和官方表单标题保留。

## Agent 与停止条件

- 先由一个实现 Agent 完成实现并退出，再由一个独立审查 Agent 审查；不得并行写同一范围，不得创建下级 Agent。
- 审查只能修复 TASK-020 范围内的明确问题；发现范围外问题必须记录并停止扩展。
- 任一数据隔离、权限、输出正确性、确认失效或回归证据缺失，不得标记 Done。
- 真实 Clerk、生产服务和隧道行为不在本卡内伪称通过，继续由 TASK-019 验证。

## 风险和注意事项

- 如果把下载确认做成技术版本确认，用户会重新形成审核系统心智；必须使用案件信息和申请书结果的业务语言。
- 如果异常原因不能定位到字段，用户仍会在长页面中迷失；浏览器验收必须记录从阻塞原因到字段处理的路径。
- 如果使用混合语言或未确认的案件标题，必须停止并回到术语规范，不得用原型文案直接进入生产。
- 静态检查不能证明滚动、焦点、数据版本失效或下载门禁；这些必须通过浏览器和状态行为验证。
