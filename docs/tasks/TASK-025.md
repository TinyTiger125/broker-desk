## 任务名称

W1 信息整理中心 List Report 参考实现

## 背景和用户结果

当前矩阵已将 `/organize-center` 确认为 List Report 主页面，但页面仍包含异常处理和多个对象类型入口。用户需要先找到案件、主体或物件，再进入后续处理，而不是在信息整理中心直接编辑全部对象。

用户主要任务是：

> 找到案件、主体或物件，并进入后续处理。

信息整理中心负责查找、筛选、结果浏览和进入对象；不负责承担案件详情编辑，也不合并案件、主体和物件的业务权威。

## 任务目标

将 `/organize-center` 作为 Broker Desk 的第一个 List Report 参考实现候选，在不改变业务数据和权限语义的前提下验证统一的筛选、结果、空态和错误结构。

## 本次范围

- `/organize-center` 的主 Floorplan 为 `List Report`。
- 待处理、异常或需要补全的对象可以在页面局部使用 `Worklist` 结构，但不能把整个页面重新定义为 Worklist。
- 案件、主体、物件继续使用各自的数据来源、权限和领域规则。
- `OrganizeCenterObjectBrowser` 保持领域组件，不直接改造成全站通用对象浏览器。
- 只建立通用的 Filter Bar、结果结构、空态和错误状态组合；不建立第二套业务数据或保存逻辑。
- 进入对象后必须保留返回信息整理中心的筛选条件、列表上下文、滚动位置和选择状态，具体可行性以 Checkpoint A 证据为准。

## 明确不做什么

- 不修改案件保存、案件字段、案件确认或 `confirmedDataJson`。
- 不触碰 TASK-020，不实施输出中心、申请书预览、下载门禁或案件级确认。
- 不修改权限模型、租户隔离、数据库结构、API 契约或 149 项字段体系。
- 不迁移其他 List Report 页面，包括客户、主体、物件、报价、模板库和审计日志。
- 不把所有结果做成卡片；表格、结果行和窄屏等价结构按实际任务决定。
- 不进行全站 CSS 替换、导航重写、全局换皮或组件机械替换。
- 不因已有页面结构而默认现有交互正确；必须先取得真实流程证据。

## 验收标准

### Checkpoint A：当前流程审计

在真实已登录环境中，只读观察当前正式 `/organize-center`，不得修改代码、目标图或页面。

1. 进入信息整理中心；
2. 记录初始状态；

4. 记录有结果状态；
5. 记录无结果状态；

7. 打开一个案件、主体或物件；
8. 返回信息整理中心，核对筛选、滚动和选择状态。

- 每一步至少一张桌面截图；

- 区分代码事实、截图观察、推断和未验证假设；
- 若没有结果、异常或权限状态，明确记录为证据缺口，不伪造通过。

## 必须保留的权威

| 领域 | 权威 |
|---|---|
| 案件 | 当前案件数据、案件权限和案件页面既有保存语义 |

- 需要修改案件保存、输出、权限、租户或数据库；
- 需要合并案件、主体、物件的数据模型；
- 需要把 `OrganizeCenterObjectBrowser` 改造成跨领域万能组件；
- 无法在真实登录环境中确认返回上下文；

- 需要同时迁移其他 List Report 或建立全局 CSS 替换。
