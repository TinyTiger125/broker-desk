## 任务名称

W1 信息整理中心 List Report 参考实现

## 背景和用户结果

当前矩阵已将 `/organize-center` 确认为 List Report 主页面，但页面仍包含异常处理和多个对象类型入口。用户需要先找到案件、主体或物件，再进入后续处理，而不是在信息整理中心直接编辑全部对象。

用户主要任务是：

> 找到案件、主体或物件，并进入后续处理。

信息整理中心负责查找、筛选、结果浏览和进入对象；不负责承担案件详情编辑，也不合并案件、主体和物件的业务权威。

## 任务目标

将 `/organize-center` 作为 Broker Desk 的第一个 List Report 参考实现候选，在不改变业务数据和权限语义的前提下验证统一的筛选、结果、空态和错误结构。

## 本次范围

- `/organize-center` 的主 Floorplan 为 `List Report`。
- 待处理、异常或需要补全的可靠对象可以在页面局部使用 `Worklist` 结构，但不能把整个页面重新定义为 Worklist。
- W1 只交付案件、主体、物件三个可靠对象入口；待归属资料入口、列表、数量和状态徽章因缺少具体对象归属权威而冻结，不代表资料为零或页面已完成。
- `/import-center` 继续负责导入任务、处理状态、映射和失败恢复；W1 不把 `targetEntity`、案件导入关联或处理状态解释为具体主体/物件归属。
- 案件、主体、物件继续使用各自的数据来源、权限和领域规则。
- `OrganizeCenterObjectBrowser` 保持领域组件，不直接改造成全站通用对象浏览器。
- 只建立通用的 Filter Bar、结果结构、空态和错误状态组合；不建立第二套业务数据或保存逻辑。
- 进入对象后，浏览器历史返回必须保留 `type`、`q`、`lifecycle`、`page`、列表滚动和触发对象链接焦点；不建立或恢复独立选择状态。一级导航“整理信息”仍返回对象选择器并重置临时列表上下文。
