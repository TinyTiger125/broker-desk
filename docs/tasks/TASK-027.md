## 任务名称

W2 客户索引 List Report 参考迁移

## 背景和用户结果

W2 客户索引 List Report 参考迁移。`/clients` 回答：

> 我要找到哪一个客户，并判断下一步跟进什么？

客户与主体是不同业务对象。客户阶段、用途、温度和跟进排序属于客户经营/跟进语义，不得套用案件的待处理、资料不足、整理完成或输出准备状态，也不得套用主体和物件的生命周期模型。

## 本次范围

本任务只允许进行 Checkpoint A 真实登录流程只读审计。只观察真实已登录的非生产环境中的 `/clients`，未经产品负责人复审，不进入目标结构、实现或页面迁移。

### 审计边界

只观察真实已登录的非生产环境中的 `/clients`。开始前记录：

- 当前 HEAD、分支和工作区状态；
- 页面 URL、审计时间、视口、浏览器缩放和设备像素比；
- 脱敏后的用户角色、租户边界和数据环境；
- 当前数据是否为合成或非生产数据。

不得为了形成结果创建、修改、归档或删除客户数据。没有某类状态或错误时，记录为 `UNVERIFIED`，不得人为制造。

## 风险和注意事项

### 产品问题

审计报告必须回答：

- 阶段、用途、温度是独立筛选，还是重复表达同一判断；
- “温度”是否是当前业务人员能够理解并使用的术语；
- 默认排序是否对应真实跟进任务；
- 快速创建是高频必要动作，还是挤占列表主任务；
- 列表信息是否足够区分同名客户；
- 客户与主体入口是否重复，是否会让用户不知道该进入哪里；
- 手机端是有效重排、横向表格，还是发生信息丢失；
- 打开客户后返回是否保留列表上下文；
- 正常客户是否安静展示，需要跟进的状态是否获得合理强调。
