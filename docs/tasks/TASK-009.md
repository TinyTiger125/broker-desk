# TASK-009: 解决首页可输出状态歧义

- 状态: Proposed
- 优先级: P1
- 负责人: 设计者、实现者、独立审查者
- 依赖关系: TASK-003

## 任务名称

统一首页的 未输入、确认待处理 和 可输出 状态及主要 CTA。

## 背景和用户结果

经纪人能在首屏判断当前案件缺什么、下一步是什么。

## 本次范围

- 首页当前任务、输出 readiness 卡片和主要 CTA。
- 对应首页回归断言。
- 一个有缺失字段和一个可输出案件的验证场景。

## 明确不做什么

- 不重做整个首页。
- 不新增报表、任务系统或业务模块。
- 不改变输出门禁本身。

## 依赖关系

TASK-003。

## 验收标准

1. 同一案件只呈现一个明确的主状态。
2. CTA 指向当前未解决的下一步。
3. 缺字段时不会显示为可输出。
4. 回归脚本与批准的产品文案一致。

## 预计涉及的模块

首页、输出 readiness helper 和首页回归断言。

## 风险和注意事项

先确认 TASK-003 的输入状态定义，避免首页创造第二套状态机。

## 验证命令

npm run lint
npm run test:regression
还必须完成缺失字段和可输出两种浏览器场景。

## 当前状态

Proposed。
