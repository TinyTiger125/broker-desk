# TASK-003: 输入资料合并完成状态闭环

- 状态: Proposed
- 优先级: P0
- 负责人: 实现者 / 独立审查者
- 依赖关系: TASK-002

## 任务名称

让输入资料追加或合并从选择目标闭环为确认、保存、结果、继续核对。

## 背景和用户结果

经纪人知道资料写入哪个案件，成功、取消、冲突和失败不会被伪装成成功。

## 本次范围

- 输入审查页目标选择、显式确认和保存状态。
- 合并相关 Server Action 的结果状态。
- 成功、取消、冲突、失败和刷新恢复的聚焦回归。

## 明确不做什么

- 不修改模板库、官方模板发布或实体生命周期。
- 不重写整个输入页面。
- 不扩展新的文件类型或 AI 能力。

## 依赖关系

TASK-002。

## 验收标准

1. 未选择目标不能提交。
2. 选择目标后必须显式确认。
3. 提交中显示保存状态并阻止重复提交。
4. 成功后显示合并、跳过、冲突或失败摘要。
5. 结果提供进入下一步核对的入口。
6. 刷新后结果来自持久化状态。

## 预计涉及的模块

src/components/input-extraction-review.tsx、src/app/actions.ts、导入和案件数据访问模块。

## 风险和注意事项

合并写入涉及案件归属和审计，不能由客户端字段决定租户或目标权限。

## 验证命令

npm run typecheck
npm run lint
npm run test:import-failure-recovery
浏览器验证选择、取消、成功、失败和刷新恢复。
