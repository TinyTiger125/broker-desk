## 任务名称

W2：导入资料 `/import-center` Wizard 参考迁移

## 背景和用户结果

围绕一个用户结果审计 `/import-center`：

> 用户能够把资料送入系统，理解系统正在处理什么，只处理真正的异常，并明确资料最终进入新案件、既有案件追加或案件合并中的哪一条路径。

Wizard 只作为连续决策外壳，不机械拆成大量页面步骤。推荐的业务边界是：

1. 选择或上传资料；
2. 系统处理；
3. 只处理识别异常、归属问题和必要补充；
4. 选择新建、追加或合并；
5. 确认本次导入结果；
6. 进入对应案件或整理任务。

本阶段不授权修改任何业务代码或底层数据能力。

## 三、当前真实流程（已从代码核对）

### 1. 进入与选择入口

- 正式入口是 `/import-center`，页面读取 `source.read` 租户会话；上传和处理动作另行要求 `source.upload`。
- 页面首屏同时给出“新开案件”“新建主体”“新建物件”三个创建入口，以及“已有文件时从这里开始”的资料上传区。三者是业务入口，不是连续 Wizard 步骤。
- 已有案件追加可通过 `targetCaseId` 和 `intake=existing` 进入；页面也会列出少量可选择案件，但当前入口仍把创建、选择案件和上传并列展示。
- 页面支持 `job`、`xlsxJob`、`targetCaseId`、`intake` 和 `advanced` 查询参数，用于恢复或聚焦某一条导入记录。

### 2. 上传

- 身份资料使用 `IdentityDocumentUploadForm`，支持 PDF/图片、多文件、单文件与总大小的客户端限制；提交到 `uploadAndParseIdentityDocumentAction` 或对应队列路径。
- Excel 使用 `ExcelDocumentUploadForm`，客户端只检查 `.xlsx` 扩展名；提交到 `uploadAndParseExcelAction`。
- 服务器端上传路径分别是 `/api/input-files/identity` 与 `/api/input-files/upload`，均先经过非生产/生产就绪检查、Clerk 租户身份和 `source.upload` 权限，再将文件放入私有导入队列。
- 返回结果包含 `jobId`、`requestId` 和后续处理 URL；上传成功首先代表“已进入处理队列”，不代表案件已形成或已经可以输出。

### 3. 处理与轮询

- `ExcelImportQueueProcessor` 在同源会话中调用 `/api/input-files/[jobId]/process`，对 `queued`/`processing` 轮询；状态进入 `mapped` 或 `completed` 后跳转到资料复核。
- 非生产处理器实际调用 `processIdentityImportJob` 或 `processExcelImportJob`；生产路径返回队列状态并依赖外部 worker/document reader 就绪条件。
- `HubImportJobItem.status` 的当前权威值为 `queued`、`processing`、`mapped`、`completed`、`failed`。它是处理状态权威，不是案件完整度、输出资格或具体主体/物件归属权威。
- Excel 处理器会读取租户范围内的私有附件，检查工作簿结构、工作表和单元格限制，提取资料并将任务标为 `mapped`；失败时写入错误摘要和审计事件。

### 4. 识别结果与当前复核

- `InputExtractionReview` 当前显示识别字段、低置信度数量、复核进度和字段级状态；用户可以将字段标记为 `suggested`、`accepted`、`edited`、`unknown` 或 `rejected`。
- 当前界面提供“接受可读字段”等批量辅助动作，但整体心智仍然是逐字段确认；正常识别结果没有真正安静地进入案件数据。
- 识别结果可以进入三条保存分支：保存为新案件、追加到指定案件、或选择候选后合并到既有案件。保存动作会写入确认事实、合并历史、来源任务关联、修正事件和审计记录，并跳转案件或继续整理。
- 合并候选由 `src/lib/case-merge.ts` 基于案件/申请人/物件等字段计算候选和冲突提示；这是候选建议，不应被解释为自动归属权威。

### 5. Excel 映射与高级区

- `advanced=1` 会在同一 `/import-center` 路由展开创建导入任务、字段映射、自动映射、校验、历史、附件和失败重试等操作。
- `src/lib/import-mapping.ts` 提供目标字段选项和必填/未知目标校验；`actions.ts` 中的映射、自动映射、校验解决和重试动作均有独立权限与审计记录。
- 这部分是批量台账导入和运维/配置工作流，与普通用户的“上传资料并进入案件”主任务不同。当前用查询参数隐藏/展开，不等于已经形成清楚的产品分层。

### 6. 失败与 422 人工恢复

- 处理端在不支持的来源或处理失败时可返回 HTTP `422`；生产就绪、认证或外部处理器缺失时也可能返回 `503`，认证/权限错误还可能返回相应会话错误。
- 失败任务会保留 `failed`、错误摘要和不透明 `requestId`，前端使用 `role="alert"` 显示通用失败文案并提供重新读取按钮。
- 当前界面没有把“资料内容需要人工处理的 422”和“服务/配置不可用的 503”明确区分；用户看到的往往都是“读取失败，请重新尝试”。因此“422 可人工恢复”在底层存在，但主流程中的业务含义尚未清楚表达。

### 7. 当前完成信号

- `mapped` 或 `completed` 只说明导入处理/映射阶段达到相应状态；它们不自动说明资料已经被用户接受、已经归入具体案件、案件已经完整或可以输出。
- 识别复核保存成功后会跳转到案件，批量台账导入完成后会显示成功/跳过结果并引导到整理信息；不同来源没有同一个“本次导入已完成”的统一结果摘要。
- 因此当前用户可能知道“文件读取完了”，但不一定知道“资料是否已进入哪个案件、哪些内容仍待处理、下一步应进入案件还是整理中心”。

## 五、事实、推断与未验证项

### 已验证事实

- 当前页面确实同时包含创建入口、两类文件上传、队列处理、识别复核、Excel 映射、历史和高级配置区。
- 处理状态和失败恢复存在明确的代码路径；`failed`、错误摘要、`requestId` 和重试动作均已实现。
- 新建、追加和合并是现有保存动作的不同分支，并写入来源/合并/审计信息。
- `targetCaseId` 可以表达具体案件追加；合并候选来自字段比较算法，不等于已经确认的归属。
- 处理权限、租户范围和私有附件读取在现有服务端路径中存在；本任务不需要重复定义它们。

### 基于证据的推断

- `/import-center` 当前更像“上传入口 + 运营控制台 + 识别审核器”的叠加，而不是一条连续的 Wizard。
- `InputExtractionReview` 的字段级确认和置信度展示会把 AI 的不确定性转化为用户的逐项审核劳动，与已批准的异常驱动原则冲突。
- `advanced=1` 能隐藏部分复杂内容，但不能解决主任务、异常任务和批量台账运维之间的职责混杂。
- `mapped`/`completed` 的技术状态不足以单独承担用户可见的“导入完成”语义；需要以现有保存结果和目标案件关联共同说明结果，不能新造完成算法。

### 尚未验证

- 未在本轮重新启动真实登录环境或上传真实测试文件，因此上传→处理→复核→新建/追加/合并的连续浏览器体验仍是 `UNVERIFIED`。
- 各类真实资料的 OCR 成功率、处理耗时和 422 触发比例未测量。
- PDF、扫描和手动来源在当前页面中是否有完整可继续的用户路径，未通过真实运行确认。
- `sourceImportJobIds`、案件关联和处理状态能否支持所有资料类型的明确归属，未宣称可以。
- 窄屏和键盘下的上传、异常处理、追加/合并选择、重试和返回上下文未验证。

## 六、推荐的单一 Wizard 结构

推荐把 `/import-center` 收敛为一条连续但可回退的导入流程，保留现有 API、动作和数据权威：

1. **选择资料**：选择资料类型并上传；若是追加，先选择或确认具体案件；新建、追加、合并是后续落点决策，不在首屏同时展开成三个互相竞争的创建卡片。
2. **系统处理中**：显示已接收、处理中或需要等待的状态。正常 `queued`/`processing`/`mapped` 只给用户必要进度，不展示置信度和候选细节。
3. **只处理问题**：仅展示明确冲突、格式错误、缺失的必要信息、归属不明或无法可靠决定的内容；原始资料、候选值和来源按需展开。正常读取结果直接作为候选案件事实继续，不要求逐字段确认。
4. **选择落点**：明确显示“新建案件”“追加到当前案件”“合并到候选案件”三种业务结果；追加必须绑定具体案件，合并必须显示候选理由和用户确认，不把算法候选当自动归属。
5. **确认导入结果**：显示目标案件、已写入/未写入/仍待处理的摘要和下一步；明确告诉用户资料是否已进入案件，提供进入案件或整理任务的单一主操作。

这不是新增数据模型或新的保存系统，而是对现有页面编排和结果表达的收敛。若现有权威无法支持某个状态或结果，就省略该表达并报告，不用占位文案补齐。
