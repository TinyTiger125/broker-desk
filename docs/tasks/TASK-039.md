## 任务名称

经营主体、成员权限与内部数据可见性基础能力（TASK-039 / W8）

## 背景和用户结果

Broker Desk 按经营主体销售，不按账号或席位销售。一个经营主体拥有一份订阅和多个成员；Clerk 只确认身份，Broker Desk 决定成员关系、公司权限、案件/人物/物件可见范围和共同工具访问。经营主体创建本身不等于正式商业服务资格：正式生产必须同时满足有效订阅、有效试用或平台批准状态；受控非生产环境可允许测试经营主体创建。

本任务最终要证明：新负责人可以创建经营主体并进入工作区，同时原子地成为本地用户、该经营主体的 active membership、公司负责人和当前活动工作区成员；负责人可以邀请成员，成员只能在受邀邮箱、目标经营主体和接受身份一致时接受邀请，状态经过“邀请中 → 已接受并使用中 → 已暂停/已移除”；公司的表格管理员可以管理公司表格，普通成员只能使用已发布表格；案件、人物和物件默认仅自己可见，主动改为公司成员可见后只增加查看权，不自动增加修改权；成员被暂停或移除后立即失去访问权，公司数据仍由经营主体保留。

## 垂直切片顺序

### 0. 现状保护与技术合同

只读盘点 Clerk 身份映射、用户/经营主体/成员表、现有邀请 Action、工作区选择、八角色权限、案件/客户/物件查询、附件/输出读取和审计。固定旧登录、旧工作区和 TASK-038 旧入口的回退边界。不得修复业务代码或补造成员关系。

### 1. 身份、经营主体创建与邀请加入

用户结果：

```text
注册或登录 → 创建经营主体 → 自动成为公司负责人 → 进入工作区
负责人邀请邮箱 → 成员登录/注册 → 接受邀请 → 建立成员关系 → 进入同一工作区
无经营主体关系 → “你尚未加入任何公司” → 创建经营主体 / 查看或接受邀请 / 重新登录
```

最小交付：真实 Clerk subject 与本地用户稳定绑定；创建经营主体时原子创建首位 active membership、负责人能力和当前工作区关系；邀请记录保存受邀邮箱和目标经营主体，接受时校验接受身份并记录“邀请中/已接受并使用中/已暂停/已移除”；拒绝/过期和工作区选择具备服务端权限；没有 membership 的用户不再循环。必须保留旧用户和旧邀请的兼容读取；生产资格另受有效订阅、有效试用或平台批准状态门禁。

### 2. 公司成员能力预设与负责人保护

用户结果：负责人可以邀请、暂停、移除和重新授权成员；成员端只看到易懂的“公司负责人”“可管理公司表单配置”“普通成员”能力，不显示席位数。底层八角色保留兼容，不因职务名自动授予权限。

最小交付：公司表格管理能力作为经营主体内可撤销的 capability/预设；负责人至少保留一名；成员移除不删除 Clerk 身份、不改变公司对象所有权；所有变化写入审计。

### 3. 仅自己可见 / 公司成员可见

用户结果：案件、人物、物件新建默认仅自己可见；用户主动分享后，同公司有该对象读取权限的成员可查看但不能因此自动修改；关联对象和文件不因案件分享而递归公开。公司空白表格和已发布公司蒙板是公司共同工具，蒙板草稿只对公司负责人和公司表格管理员开放；共享蒙板不能成为读取私有案件资料的通道。

最小交付：案件、人物、物件分别保存可见范围；生成文件继承所属案件的访问范围；所有页面、Server Action、API、附件和输出读取共用服务端授权；无权读取时统一返回拒绝/无权查看，不用客户端隐藏替代门禁；旧数据使用安全默认并可双读。

### 4. TASK-038 正式产品入口接入

用户结果：公司表格管理员从公司表格库上传、保存、重开、测试和发布；普通成员从本人有权访问的案件选择已发布公司蒙板并生成文件；同一蒙板可服务两个案件，案件资料、保证申请记录和生成文件不串联；普通成员看不到蒙板编辑入口。

最小交付：将 TASK-038 受控 harness 接入真实成员关系、公司表格权限和案件输出权限；不改变五套现有平台蒙板生产行为，不扩大案件共享规则；当前 `case.user_id` 只用于本人案件的最小闭环，跨成员共享保持平台依赖。

### 5. 离职接管与付费停止保留

用户结果：成员暂停/移除立即失去访问；公司负责人可以接管其未归属业务并留下审计；停止付费进入 30 天恢复/导出期，再封存，累计六个月后不可恢复删除。案件业务数据、付款记录和法定审计分别处理。

最小交付：先实现成员停用/移除和接管状态；订阅停止和删除期限在日本法律/合同确认前只实现受控状态机，不把六个月写成永久保管承诺。
