# TASK-006: 统一实体详情返回路径

- 状态: Proposed
- 优先级: P1
- 负责人: 实现者 / 独立审查者
- 依赖关系: TASK-002

## 任务名称

让案件、主体、物件详情或编辑页按已确认的上下文规则返回整理中心。

## 背景和用户结果

经纪人完成编辑或生命周期操作后回到正确的对象选择器，而不是无关页面。

## 本次范围

- 案件、主体、物件详情或编辑页的返回入口。
- 整理中心类型、搜索、focus 和 lifecycle returnTo 的保留规则。
- 返回路径回归。

## 明确不做什么

- 不在本卡内实施 TASK-006A。
- 不统一三类实体的全部编辑表单。
- 不修改数据模型、权限或生命周期业务规则。
- 不改变整理中心的信息架构。

## 依赖关系

TASK-002。

## 验收标准

1. 明确区分页面内返回入口和生命周期操作后的 returnTo。
2. 案件、主体、物件的上下文保留规则各有证据。
3. 返回行为在刷新和直接 deep-link 下不报错。
4. 不把 TASK-006A 的固定案件返回地址扩展成三类实体改造。

## 预计涉及的模块

案件、主体、物件编辑页、Server Action 和整理中心。

## 风险和注意事项

TASK-006A 只处理案件详情页页面内返回入口；生命周期 returnTo 留在本任务或后续明确任务中。

## 验证命令

npm run typecheck
npm run lint
npm run test:regression
浏览器验证三类页面的返回和刷新。
