# TASK-040 / W9：资料可见范围 V1

## 任务名称

资料可见范围 V1：案件、人物、物件的默认私有与公司只读可见。

## 背景和用户结果

TASK-039 的经营主体与成员基础阶段已验收并集成，但案件、人物、物件的内部可见范围尚未产品化。第一版必须让资料默认仅创建者可见，并由资料负责人逐条决定是否切换为公司成员只读可见；所有页面、搜索、导出、附件、API、关系图和生成文件都必须遵守同一可见性判断。

产品基线已确认：

1. 案件、人物、物件默认仅创建者可见。
2. 每个成员分别设置自己新建三类资料的默认范围；公司负责人不能强制公开。
3. 单条资料可由资料负责人覆盖默认范围，所有变化留审计。
4. “公司成员可见”第一版只读，不做定向分享和共同编辑。
5. 列表、详情、搜索、导出、关系图、附件、API 和生成文件统一执行可见性。
6. 公司负责人没有员工私有内容通览权，只能查看必要治理元数据。
7. PDF 生成要求操作者同时有权访问所有实际使用的来源资料；缺少任一必要权限时阻止生成。
8. 历史 PDF 内容不可变，但下载仍检查当前案件及来源资料权限。
9. 暂停或移除不自动公开或删除资料。
10. 资料接管必须独立确认、留审计；接管前负责人不能借此浏览内容。
11. 私有资料不参与公司级查重，不向其他成员泄露其存在。

## 数据语义与权限裁决

- 默认范围设置按“经营主体 membership + 成员 + 对象类型”保存；不建立全局账号级默认值。
- 三类对象的范围枚举仅允许 `仅自己可见` 和 `公司成员只读可见`。
- 新建资料的初始负责人是创建者；导入资料的初始负责人是执行导入的成员。
- `created_by` 与 `current_owner` 必须是可分别演进的概念；后续接管可以改变当前负责人。
- 旧数据能够可靠识别负责人时，迁移为该负责人私有；无法识别时进入“负责人待确认”，保持 fail-closed。
- 负责人不明的旧数据不得自动归给公司负责人、自动公开或自动删除，也不得出现在普通成员列表、搜索或导出中。
- 第一版只有资料负责人可以编辑资料、附件、关联关系和可见范围；公司成员只读可见不附带任何写能力。
- 公司负责人和表格管理员不能绕过资料负责人权限查看或编辑私有内容。
- 成员默认值的修改只影响之后新建的资料，不追溯改变已有资料；单条覆盖只影响该条资料。
- 公司表格、蒙板和平台工具继续按公司共享，不纳入案件、人物、物件可见范围。
- PDF 预览、生成和历史下载采用案件及全部实际来源资料权限的交集；缺少任一必要权限时阻止操作。
- TASK-040 只处理暂停/移除后的保留与撤权，不实现资料接管；接管流程、接管审计和长期留存另立专题。
- 私有资料不得通过查重、搜索建议、数量、关系图、附件名称、导出或错误提示泄露其存在。

## 本次范围

- 为案件、人物、物件建立统一的资料负责人和可见范围判定。
- 让每名成员配置自己新建三类资料的默认范围，并允许资料负责人逐条覆盖。
- 在列表、详情、搜索、导出、关系图、附件、API、PDF 生成和历史下载入口复用服务端可见性门。
- 公司成员可见只授予读取；编辑、接管和治理元数据使用独立能力。
- 对暂停、移除和来源资料权限变化保持安全默认，并记录可审计状态。
- 仅实现暂停/移除后的撤权与资料保留，不实现资料负责人接管流程。
- 按“实施 Agent → 独立只读审查 → Staging 黑盒验收”推进，每个切片形成可追溯版本。

实施切片建议：

1. W9.1：资料负责人、可见范围和旧数据安全默认；先完成模型、migration 和回滚演练。
2. W9.2：案件、人物、物件的服务端读取/写入门，以及列表、详情、搜索和导出。
3. W9.3：关系图、附件、API、PDF 生成和历史下载的统一来源权限门。
4. W9.4：逐条覆盖、审计、暂停/移除后的保留与撤权；完整资料接管另立专题。
5. W9.5：两名普通成员、负责人、跨经营主体和来源权限的 Staging 黑盒验收。

## 明确不做什么

- 不做定向成员分享、共同编辑、部门/门店/集团权限树。
- 不做关联对象递归公开，也不通过公司级查重泄露私有资料存在。
- 不授予公司负责人浏览全部员工私有内容的特权。
- 不在本任务完成完整成员资料接管、停付费保留/删除或法律留存规则。
- 不修改 TASK-038 产品功能、五套旧模板、Production 数据库或 Production 发布配置。
- 不把 `user_id` 直接当作公司所有权，不硬编码 Clerk 身份，不放宽跨经营主体 RLS。

## 依赖关系

- 依赖 TASK-039 经营主体与成员基础阶段已验收并集成。
- 以 TASK-038 `Done / Product Accepted and Integrated / Production Not Released` 作为 PDF、表格、历史文件和权限回归基线。
- 预计实施周期为 5–10 个工作日，不包含 Production 发布前门。

## 验收标准

- 同一公司两名普通成员互相看不到对方私有案件、人物和物件。
- 将三类对象分别切换为公司可见后，对方可以读取但不能编辑，且一种对象不会自动公开另外两种对象。
- 同一成员在两家公司可以分别设置默认值；案件、人物、物件三个默认值互相独立。
- 新建资料继承创建当时的默认值；之后修改默认值不改变旧资料；单条覆盖只改变该条资料。
- 公司可见成员只能读取，所有资料、附件、关联关系和可见范围写接口均拒绝非负责人。
- 搜索、导出、关系图、附件和 API 不泄露隐藏对象；跨经营主体读取继续拒绝。
- 公司负责人不能直接查看员工私有内容，只能读取必要治理元数据。
- 缺少任一来源资料权限时不能生成 PDF；历史 PDF 不成为权限绕过入口。
- 负责人不明的旧数据不出现在普通成员列表、搜索或导出；隐藏关联对象不能通过案件页面或 PDF 泄露。
- 暂停和移除后资料不丢失、不自动转移、不自动公开或删除；当前阶段不提供接管入口。
- 可见性变化均有审计记录；资料接管审计与长期留存属于后续专题。
- 真实 Staging 验收覆盖页面与服务端路径；未取得运行证据不得宣称通过。

## 预计涉及的模块

- 案件、人物、物件的数据模型、读取适配器和服务端授权层。
- 列表、详情、搜索、导出、关系图、附件和 PDF 预览/生成/下载入口。
- Clerk subject、tenant session、capability 和 Postgres RLS 的现有边界复用。
- 追加式数据库 migration、迁移账本、失败回滚和旧数据双读兼容。
- 对应的确定性契约、集成检查和 Staging 验收记录。

## 风险和注意事项

- 可见性必须 fail-closed；客户端隐藏按钮不能替代服务端授权。
- 旧数据未设置范围时必须有安全默认，不能因为迁移或回退短暂公开。
- 生成文件必须在生成时检查全部来源权限，历史下载仍检查当前案件和来源权限。
- 暂停、移除和接管不能自动迁移、公开或删除资料。
- 任何影响 TASK-039 成员、经营主体或权限链路的修改，必须回归已有 A/B 和跨经营主体基线。
- 追加式 migration 需记录兼容性、失败状态、回滚边界；不在本任务接触 Production。
